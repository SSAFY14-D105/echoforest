# 📊 STT 기술 비교 보고서 (Technical Strategy Report)

게임 개발을 위한 3가지 음성 인식(STT) 기술의 성능 분석 및 비교 결과입니다.

---

## 🏎️ 1. 성능 비교 요약 (Executive Summary)

| 항목 | v1: Local Whisper (Client JS) | v2: Google Web Speech API (Browser VAD) | ⚡ v3: Python AI Server (FastAPI + CUDA) |
| :--- | :--- | :--- | :--- |
| **핵심 기술** | Transformers.js (WebAssembly) | Google Cloud (Browser Native) | **Faster-Whisper (CUDA)** |
| **처리 위치** | 🖥️ 사용자 브라우저 (On-Device) | ☁️ 구글 클라우드 (Cloud) | 🚀 **로컬 서버 (On-Premise GPU)** |
| **지연 시간** | 🐢 매우 느림 (3~5초 이상) | ⚡ 빠름 (실시간 스트리밍) | ⚡ **매우 빠름 (0.2~0.5초)** |
| **정확도** | ⚠️ 낮음 (Tiny 모델 한계) | ✅ 우수 (구글 데이터 셋) | ✅ **최상 (Base/Medium 모델 사용)** |
| **교육적 가치** | ⭐ (AI 모델 직접 구동) | ❌ **없음 (API 단순 호출)** | ⭐⭐⭐ **(AI 파이프라인 직접 구축)** |
| **커스터마이징** | ❌ 불가 (제공된 모델만 사용) | ❌ **불가 (Black Box)** | ✅ **가능 (VAD, 빔서치, 모델 교체)** |
| **한계점** | CPU 부하 심함 | **학습/연구 불가능 (단순 사용)** | 환경 설정 복잡함 |

## 🔍 2. 버전별 상세 분석

### 🔴 v1: Client-Side (Local Whisper)
*   **방식**: 브라우저에서 WebAssembly로 AI 모델을 직접 돌리는 방식.
*   **장점**: 서버가 필요 없고, 완전한 오프라인 실행 가능.
*   **단점**: 웹 브라우저의 한계로 인해 CPU 부하가 심하고 속도가 느려 실시간 게임에는 부적합합니다.

### 🟡 v2: Google Web Speech (Web API)
*   **방식**: 크롬 브라우저 내장 API를 사용 (구글 서버로 전송).
*   **장점**: **성능은 매우 훌륭합니다.** 빠르고 정확하며, 구현도 쉽습니다.
*   **단점 (프로젝트 취지 불일치)**:
    *   **"Black Box"**: 내부가 어떻게 동작하는지 알 수 없고, 단순히 남이 만든 API를 가져다 쓰는 수준입니다.
    *   **"AI 역량 강화" 불가**: SSAFY 프로젝트의 핵심 목표인 *"AI 기술에 대한 깊은 이해와 학습"*을 달성하기 어렵습니다.
    *   **게임 로직 결합 한계**: 우리가 원하는 대로 VAD(음성 감지) 민감도를 조절하거나, 특정 단어 가중치를 주는 등의 깊은 튜닝이 불가능합니다.

### 🟢 v3: Python AI Server (최종 선택)
*   **방식**: 별도의 Python 프로그램이 GPU(CUDA)를 사용해 직접 AI 파이프라인을 구축.
*   **선정 이유 (Why v3?)**:
    *   **Technical Challenge**: 단순 API 호출을 넘어, 실제로 **AI 모델을 서빙하고 최적화하는 과정**을 경험할 수 있습니다.
    *   **Full Control**: VAD 임계값, 모델 크기, 빔 서치 등을 직접 튜닝하여 **"게임에 딱 맞는 AI"**를 깎아낼 수 있습니다.
    *   **성능**: v2만큼 빠르면서도, 우리가 모든 것을 제어할 수 있습니다.

## 💡 3. 최종 제언
팀 프로젝트의 성공적인 **"Voice Co-op Game"** 구현을 위해 **v3 (Python AI Server)** 아키텍처를 채택합니다.
1.  **속도**: 즉각적인 스킬 발동 가능.
2.  **안정성**: 게임 프레임 드랍 방지.
3.  **확장성**: 추후 멀티플레이어 환경에서도 구조 변경 없이 적용 가능.
