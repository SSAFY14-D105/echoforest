# 🌍 개념 정리: 로컬(Local) vs 서버(Server) vs 클라우드(Remote)

"로컬"이라는 단어가 상황에 따라 다르게 쓰여서 헷갈리셨죠? 명쾌하게 "컴퓨팅 자원을 누가, 어디서 쓰는가"로 분류해 드립니다.

---

## 1. 📂 분류표 (Taxonomy)

| 구분 | 1. Client-side (v1) | 2. Self-hosted Server (v3) | 3. Remote Cloud (v2) |
| :--- | :--- | :--- | :--- |
| **별명** | 브라우저 로컬 (Browser) | 로컬 서버 (Localhost) | 클라우드 API (SaaS) |
| **실행 위치** | 크롬 브라우저 탭 안 | 내 컴퓨터의 **터미널(Python)** | 미국 구글 데이터센터 |
| **계산 자원** | 내 CPU (WASM) | **내 GPU (RTX 4050)** | 구글 TPU |
| **특징** | 설치 X, 느림 | **설치 O, 빠름 (최강)** | 설치 X, 빠르지만 네트워크 딜레이 |
| **비유** | 자전거 (내 다리) | **스포츠카 (내 차고)** | 택시 (남의 차) |

---

## 2. 🧐 상세 Q&A

### Q1. "v1(Local Whisper)은 왜 GPU를 안 쓰고 CPU로 돌렸나요?"
*   **이유**: **"브라우저의 보안 및 기술적 한계"** 때문입니다.
*   크롬 브라우저는 웹사이트가 사용자의 그래픽카드(CUDA)를 함부로 끌어다 쓰지 못하게 막혀 있습니다. (해킹/채굴 방지)
*   `WebGPU`라는 신기술이 나오고 있긴 하지만, 아직 파이썬의 `CUDA`만큼 강력하고 직접적인 제어를 할 수 없습니다.
*   그래서 v1은 울며 겨자 먹기로 느린 **CPU(WebAssembly)**를 썼던 것입니다.

### Q2. "v3(FastAPI)도 내 컴퓨터에서 도는데 왜 '서버'라고 하나요?"
*   브라우저(크롬) 입장에서 보면, 요청을 보내고 응답을 받는 대상은 모두 **"서버"**입니다.
*   그 서버가 **내 컴퓨터(127.0.0.1)**에 있으면 **"로컬 서버"**라고 부르고,
*   **지구 반대편(google.com)**에 있으면 **"원격 서버"**라고 부를 뿐입니다.
*   **핵심**: v3는 브라우저 밖으로 탈출해서 **"내 컴퓨터의 주인 권한(OS & Hardware)"**을 다 가집니다. 그래서 **RTX 4050을 100% 쓸 수 있는 것**입니다.

### Q3. "그럼 로컬인가요 서버인가요?"
*   **개발자(나) 입장**: 내 컴퓨터에서 도니까 **"로컬 서버"** (개발 편의성).
*   **사용자(친구) 입장**: 내 컴퓨터로 접속해야 하니까 **"원격 서버"** (네트워크 필요).
*   **정확한 용어**: **"On-Premise (온프레미스)"** 서버입니다. (클라우드를 안 빌리고 내가 직접 운영한다는 뜻)

---

## 3. 🌐 더 정확한 구분 (Spectrum)

IT 업계에서는 크게 3가지로 나눕니다.

| 구분 | 1. On-Device (온디바이스) | 2. On-Premise (온프레미스) | 3. Cloud (클라우드) |
| :--- | :--- | :--- | :--- |
| **위치** | 사용자 주머니 속 (폰/PC) | **우리 동아리 방 (내 노트북)** | 미국 데이터센터 |
| **네트워크** | 필요 없음 (Airplane Mode O) | **필요함 (같은 와이파이)** | 필요함 (인터넷) |
| **속도** | 0ms (즉시) | **~10ms (매우 빠름)** | ~100ms+ (보통) |
| **예시** | 아이폰 Siri(일부), **v1(Whisper)** | **v3(FastAPI)**, 회사 전산실 | **v2(Google)**, AWS |
| **장점** | 보안 최강, 데이터 안 나감 | **보안/속도 균형, 고성능 장비** | 관리 편함, 무한 확장 |

> **💡 결론**:
> 유저 입장에서 볼 때, 우리가 만드는 **v3**는 "클라우드(미국)까지 안 가고, 바로 옆 친구 노트북(온프레미스)으로 쏘는 것"이라서 **클라우드보다 훨씬 응답이 빠릅니다.** 그래서 "로컬 서버"라고 불러도 무방합니다.

---

## 🎯 3줄 요약
1.  **v1 (On-Device/Browser)**: 유저 폰에서 돌림. (느려서 탈락)
2.  **v2 (Cloud)**: 구글한테 보냄. (빨랐지만 내 기술 아님)
3.  **v3 (On-Premise)**: **"내 노트북을 미니 서버로 만듦"**. (빠르고 + 내 기술 + 고성능 GPU). **이게 정답!**
