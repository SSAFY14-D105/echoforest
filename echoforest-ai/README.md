## 🎮 프로젝트 소개

### 게임 컨셉

**EchoForest(메아리 숲)**는 플레이어가 **말조심**해야 하는 협동 게임입니다.  
음성 채팅에서 부정적 발언이 감지되면 AI가 이를 탐지하여 **저주 패널티**를 발동시킵니다.

```
플레이어 발화 → Web Speech API(STT) → AI 분석 → 부정어 감지 → 저주 발동! 🔮
                                                                    ↓
                                           HP 감소, 이동속도 저하, 맵 난이도 상승
```

### 핵심 메커니즘

| 메커니즘 | 설명 |
|---------|------|
| **메아리 카운트** | 부정 발언 시 +2 증가, 임계값 도달 시 저주 발동 |
| **저주 쿨타임** | 저주 발생 후 4초간 메아리 누적 정지 |
| **저주 해제** | 특정 긍정 주문을 외쳐야 저주 해제 가능 |
| **심각도 차등** | 욕설 강도에 따라 저주 강도가 달라짐 |

### 프로젝트 차별점

- **실시간 음성 분석**: Web Speech API + AI 서버 연동으로 실시간 욕설 탐지
- **데이터 기반 최적화**: 모델 공식 권장값이 아닌 실제 게임 환경 데이터로 최적화
- **세분화된 제재**: 4단계 심각도로 저주 강도 차등 적용

- 보안이 중요한 욕설 탐지는 서버에서 처리

| 인종/국적 | 인종, 국적 차별 | 짱깨 |

# 3. 추론 (no_grad로 메모리 최적화)
with torch.no_grad():

    probs = torch.sigmoid(outputs.logits)  # 다중 레이블이므로 sigmoid

# 4. 심각도 판정

| 지표 | 의미 | 게임 관점 영향 |

## 🎯 Threshold 최적화 과정

### 문제 인식

- Smilegate 공식 권장값: **17.4%**
- 문제: 게임 내 경미한 투덜거림("바보", "화나")을 놓침
- Recall이 87.9%로 낮아 약 **12%의 욕설이 미탐지**

### 최적화 분석 결과

| Threshold | Accuracy | Precision | Recall | F1 Score | TP | FP | TN | FN | 분석 |
|:---------:|:--------:|:---------:|:------:|:--------:|:--:|:--:|:--:|:--:|:-----|
| 0.05 | 52.1% | 49.3% | 100.0% | 0.660 | 33 | 34 | 4 | 0 | ❌ 과탐지 심각 |
| 0.08 | 85.9% | 78.0% | 97.0% | 0.865 | 32 | 9 | 29 | 1 | ⚠️ FP 9건 |
| **0.10** | **95.8%** | **94.1%** | **97.0%** | **0.955** | **32** | **2** | **36** | **1** | ✅ **최적값 선정** |
| 0.12 | 97.2% | 97.0% | 97.0% | 0.970 | 32 | 1 | 37 | 1 | ✨ F1 최고점 |
| 0.15 | 95.8% | 96.9% | 93.9% | 0.954 | 31 | 1 | 37 | 2 | "화나" 미탐지 시작 |
| **0.174** | 93.0% | 96.7% | 87.9% | 0.921 | 29 | 1 | 37 | 4 | Smilegate 공식값 |
| 0.25 | 93.0% | 100.0% | 84.8% | 0.918 | 28 | 0 | 38 | 5 | FN 증가 |

### 0.10 선택 근거

1. **FP 2건으로 오제재 최소화**하면서 Recall 97% 확보
2. Smilegate 공식값(17.4%) 대비: **Recall +9.1%p**, FN 4건→1건 감소
3. 게임 특성상 "바보"(Score 0.165), "화나"(Score 0.127) 등 탐지 필요

### 공식값 vs 서비스 최적값

| 구분 | Smilegate 공식 (17.4%) | 서비스 최적 (10%) | 개선 |
|------|------------------------|-------------------|------|
| Recall | 87.9% | 97.0% | **+9.1%p** |
| FN (미탐지) | 4건 | 1건 | **-3건** |
| 용도 | 일반 혐오 표현 | 게임 채팅 환경 | - |

## 💡 개발하며 배운 핵심 인사이트

### 1. 공식 권장값 ≠ 서비스 최적값

**상황**: Smilegate unSmile 모델의 공식 threshold는 17.4%

**깨달은 점**:
- 공식 값은 **일반적인 혐오 표현** 탐지에 최적화
- 우리 서비스는 **게임 채팅 환경**이므로 사용 패턴이 다름
- **독자적인 데이터 수집 및 분석 필수**

> **결론**: 모델 개발자의 권장값을 맹신하지 말고, 실제 서비스 데이터로 검증하고 조정해야 한다.

---

### 2. Precision vs Recall 트레이드오프

**관찰 결과**:
```
Threshold ↓ (0.174 → 0.10)
→ Recall ↑ (87.9% → 97.0%)  ✅ 좋음
→ Precision ↓ (96.7% → 94.1%)  ⚠️ 약간 하락
→ FP 증가 (1건 → 2건)
```

**깨달은 점**:
- **완벽한 모델은 없다** (Precision과 Recall은 트레이드오프)
- 서비스 특성에 따라 어느 쪽을 우선할지 결정 필요
- 게임 환경에서는 **욕설 미탐지(FN)가 오제재(FP)보다 더 치명적**

> **결론**: 둘 다 높일 순 없으니, **비즈니스 우선순위**에 따라 선택해야 한다.

---

### 3. 싱글톤 패턴의 실질적 효과

**Before**: 매 요청마다 모델 로드
```python
def predict(text):
    model = load_model()  # 5~10초 소요
    return model.predict(text)
```

**After**: 서버 시작 시 1회만 로드 (싱글톤)
```python
_model_instance = None

def get_model():
    global _model_instance
    if _model_instance is None:
        _model_instance = UnSmileModel()
        _model_instance.load()  # 서버 시작 시 1회만
    return _model_instance
```

**결과**: 응답 속도 **100배 향상** (~5초 → ~50ms)

> **결론**: 디자인 패턴은 단순한 이론이 아니라, 실제 서비스 성능에 **치명적 영향**을 미친다.

---

### 4. CPU vs GPU 성능 차이의 실체

| 작업 | CPU | GPU | 배속 |
|------|-----|-----|------|
| 단건 추론 | 50ms | 5ms | **10배** |
| 배치(32개) | 1,200ms | 30ms | **40배** |

**깨달은 점**:
- GPU는 **배치 처리**에서 진가를 발휘 (40배!)
- CUDA 설치/설정이 어렵지만 **투자 대비 효과 확실**

> **결론**: AI 서비스에서 GPU는 선택이 아닌 필수. 특히 다수 사용자 동시 처리 시 필수적이다.

---

### 5. 실제 데이터의 중요성

**초기 접근**: 임의로 만든 테스트 케이스 사용

**문제 발견**:
- "ㅋㅋㅋ", "ㅎㅎㅎ" 같은 채팅 용어는 실제 **음성**에 없음
- "피하세요", "뛰세요" 같은 게임 명령어 패턴 발견 안 됨

**개선**: 실제 게임 음성 채팅 패턴 반영한 **구어체 데이터셋 71개** 구축

> **결론**: 좋은 모델보다 좋은 데이터가 먼저다. 실제 서비스 환경을 반영한 데이터셋이 핵심이다.

---

### 6. 오분류 케이스 분석과 대응

**발견한 오분류 케이스** (Threshold 0.1 기준):

| 텍스트 | 실제 | 예측 | Score | 원인 분석 |
|--------|------|------|-------|----------|
| "대박이다 이걸 피하네" | Clean | Mild | 0.206 | '피하다' 단어가 부정 맥락에서 학습 |
| "오른쪽으로 피하세요" | Clean | Mild | 0.104 | 게임 명령어인데 오탐 |
| "이거 게임이 너무 어렵잖아" | Negative | Clean | 0.056 | 단순 불만이 낮은 점수 |

**대응 방안**:
- 게임 특화 명령어("피하세요", "뛰세요" 등) **화이트리스트** 적용 고려
- 맥락 이해를 위한 **문장 단위 분석** 필요성 인식
