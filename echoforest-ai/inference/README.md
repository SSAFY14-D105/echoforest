# 🤖 EchoForest AI Inference Server

Smilegate **unSmile** 모델 기반의 한국어 혐오 발언 탐지 API 서버입니다.

> 📖 전체 시스템 개요는 [echoforest-ai/README.md](../README.md)를 참조하세요.

# 🏆 Key Technical Achievements (개발 성과 및 배운 점)

이 AI 서버를 개발하며 고민했던 기술적 도전과 해결 과정입니다.

### 1. Singleton 패턴으로 추론 속도 100배 향상
- **문제**: BERT 모델(~400MB)을 매 요청마다 로드하면 응답에 **5~10초**가 소요되어 실시간 게임에 부적합했습니다.
- **해결**: `model.py`에 싱글톤 패턴을 적용하여 서버 시작 시 모델을 메모리에 한 번만 상주시키도록 변경했습니다.
- **결과**: 첫 요청 이후 평균 응답 속도 **~50ms** 달성 (약 100배 향상).

### 2. 정밀한 Threshold 최적화 (F1 Score 0.96)
- **도전**: "바보", "멍청이" 같은 가벼운 비속어는 잡아야 하지만, 정상적인 대화를 욕설로 오판(False Positive)해서는 안 됩니다.
- **해결**: 90개의 실제 대화 샘플(정상, 경미, 욕설, 혐오)로 테스트를 진행하여 Threshold를 정밀하게 조정했습니다.
- **결과**: 초기 **17.4%**에서 **10.0%**로 조정하여, 오제재 없이 경미한 욕설 탐지율(Recall)을 극대화했습니다. (F1 Score: 0.962)

### 3. 차등 제재를 위한 4단계 심각도(Severity) 시스템
- **기획**: 욕설이라고 무조건 강퇴하면 게임 경험이 나빠집니다.
- **구현**: 모델의 Confidence Score를 구간별로 나누어 4단계 심각도를 설계했습니다.
  - **Mild**: 가벼운 경고 (게임 영향 없음)
  - **Severe**: 패널티 부여 (속도 감소)
  - **Critical**: 즉시 차단 (행동 불가/강퇴)
- **가치**: 단순 이진 분류(욕설 O/X)를 넘어 **게임 기획 의도에 맞는 유연한 제재 시스템**을 구축했습니다.

### 4. 하이브리드 추론 아키텍처 (On-device vs Server)
- **전략**: 모든 AI 처리를 서버에서 하면 비용과 지연시간이 문제입니다.
  - **On-device (Client)**: 빠른 반응이 필요한 '모션 인식(MediaPipe)'과 '긍정어 탐지'는 브라우저에서 처리.
  - **Server-side**: 보안이 중요하고 모델이 무거운 '욕설 탐지(UnSmile)'는 서버에서 처리.
- **배운 점**: 각 AI 태스크의 특성(실시간성 vs 정확성/보안)에 따라 **컴퓨팅 자원을 효율적으로 분배**하는 설계를 경험했습니다.

# 📑 Technical Report: Threshold & Logic

## 1. Threshold 최적화 분석 (2026-01-22 수행)

### 1.1 실험 개요
- **목적**: 게임 내 채팅 환경에서 **"바보", "화나" 같은 경미한 부정어까지 포함**하여 폭넓게 탐지하기 위함
- **데이터셋**: 총 90개 샘플 (정상: 50, 경미: 15, 강한욕설: 16, 혐오: 9)

### 1.2 Threshold별 성능 지표 (실측 데이터)

테스트 결과, **Threshold 0.10 (10%)**에서 가장 높은 F1 Score(0.962)를 기록했습니다.

| Threshold | Accuracy | Precision | Recall | F1 Score | TP | FP | TN | FN | 비고 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| 0.05 | 46.7% | 45.5% | **100.0%** | 0.625 | 40 | 48 | 2 | 0 | ⚠️ 과탐지 심각 |
| **0.10** | **96.7%** | **97.4%** | **95.0%** | **0.962** | **38** | **1** | **49** | **2** | ✅ **최적 선정 (F1 최고점)** |
| 0.15 | 94.4% | 100.0% | 87.5% | 0.933 | 35 | 0 | 50 | 5 | "지루해", "화나" 미탐지 |
| 0.174 | 92.2% | 100.0% | 82.5% | 0.904 | 33 | 0 | 50 | 7 | "바보" 미탐지 |
| 0.30 | 91.1% | 100.0% | 80.0% | 0.889 | 32 | 0 | 50 | 8 | 미탐지 증가 |

### 1.3 최적값 선정 근거: **10.0% (0.1)**

기존 17.4%에서 **10%로 하향 조정**했습니다.

1.  **경미한 부정어 탐지 강화**: "바보"(0.165), "별로야"(0.111) 등 일상적인 부정 표현도 감지해야 합니다.
2.  **높은 성능**: **F1 Score 0.962**로, 오제재 1건(FP) 대비 탐지 이득(TP)이 압도적으로 큽니다.

## 2. 심각도(Severity) 분류 알고리즘

### 2.1 분류 기준표

|:---:|:---:|:---:|:---|:---|
| **Clean** | 0 | 0.0% ~ 9.9% | 완전한 정상 발화 | 제재 없음 |

| **Critical** | 1 | 80.0% ~ 100.0% | 매우 심한 욕설, 인신공격 | **즉시 퇴장** / 행동불가 |

# 📡 통합 API 명세

### 1. 헬스 체크
- **URL**: `GET /api/v1/health`
- **설명**: 서버 상태 및 모델 로드 여부 확인
- **Response**: `{ "status": "healthy", "model_loaded": true }`

### 2. 텍스트 분석 (기본)
- **URL**: `POST /api/v1/analyze`
- **Body**: `{ "text": "분석할 내용" }`
- **Response**:
```json
{
  "is_negative": true,
  "label": "악플/욕설",
  "confidence": 0.918,
  "severity": 1,
  "severity_label": "critical"
}
```

### 3. 실시간 게임 분석 (v2 예정)
- **URL**: `POST /api/v1/analyze/realtime`
- **설명**: 욕설 감지 시 게임 서버로 패널티 요청을 비동기로 전송
- **Body**: `{ "text": "...", "userId": "...", "roomId": "..." }`
- **Response**: 프론트엔드용 빠른 응답 (패널티 전송 여부 포함)
