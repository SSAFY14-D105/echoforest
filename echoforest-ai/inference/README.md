## 핵심 성능 수치

| 지표 | 값 | 측정 기준 |
|------|-----|----------|
| **F1 Score** | **0.955** | Threshold 0.1, 71개 실제 음성 샘플 |
| **Accuracy** | **95.8%** | 전체 정확도 |
| **Precision** | **94.1%** | 욕설 판정 정밀도 |

| **GPU 가속** | **10배** | 단건 추론 기준 (50ms → 5ms) |

## Threshold 최적화 상세 분석

전체 테스트 결과 (데이터: 71개 실제 음성 샘플)

| Threshold | Accuracy | Precision | Recall | F1 Score | TP | FP | TN | FN | 분석 |
|:---------:|:--------:|:---------:|:------:|:--------:|:--:|:--:|:--:|:--:|:-----|
| 0.05 | 52.1% | 49.3% | 100.0% | 0.660 | 33 | 34 | 4 | 0 | ❌ 과탐지 심각 (정상어 대부분 오판) |
| 0.08 | 85.9% | 78.0% | 97.0% | 0.865 | 32 | 9 | 29 | 1 | ⚠️ FP 9건 (오제재 위험) |
| **0.10** | **95.8%** | **94.1%** | **97.0%** | **0.955** | **32** | **2** | **36** | **1** | ✅ **최적값 (균형점)** |
| 0.12 | 97.2% | 97.0% | 97.0% | **0.970** | 32 | 1 | 37 | 1 | ✨ F1 최고점 (0.1과 큰 차이 없음) |
| 0.15 | 95.8% | 96.9% | 93.9% | 0.954 | 31 | 1 | 37 | 2 | "화나"(0.127) 미탐지 시작 |
| 0.174 | 93.0% | 96.7% | 87.9% | 0.921 | 29 | 1 | 37 | 4 | Smilegate 공식값, Recall 낮음 |
| 0.20 | 93.0% | 96.7% | 87.9% | 0.921 | 29 | 1 | 37 | 4 | 0.174와 동일 |
| 0.25 | 93.0% | 100.0% | 84.8% | 0.918 | 28 | 0 | 38 | 5 | FP=0이나 FN 증가 |
| 0.30 | 91.5% | 100.0% | 81.8% | 0.900 | 27 | 0 | 38 | 6 | 경미한 욕설 놓침 |

**성능 지표 설명**:
- **TP** (True Positive): 욕설을 욕설로 판정 (정답)
- **FP** (False Positive): 정상을 욕설로 오판 (오제재, 치명적)
- **TN** (True Negative): 정상을 정상으로 판정 (정답)
- **FN** (False Negative): 욕설을 정상으로 오판 (미탐지)

**최적값 선정 근거**:
1. **0.10 선택 이유**: FP 2건으로 오제재 최소화하면서 Recall 97% 확보
2. **0.12와 비교**: F1 Score는 0.12가 0.015 높지만, 실질적 차이 미미하므로 더 보수적인 0.10 선택
3. **0.174(공식값) 대비**: Recall +9.1%p, FN 4건→1건으로 감소

# 🔧 해결한 주요 문제들

## 1. 모델 로딩 속도 문제
**문제**: 
- BERT 모델(400MB)을 매 요청마다 로드 시 **5~10초** 소요
- 첫 요청 응답까지 최대 10초 대기 (실시간 게임에 치명적)

**해결**:
```python
# 싱글톤 패턴 적용 (model.py)
_model_instance = None

def get_model():
    global _model_instance
    if _model_instance is None:
        _model_instance = UnSmileModel()
        _model_instance.load()  # 서버 시작 시 1회만 실행
    return _model_instance
```

**결과**:
- 첫 요청 이후 응답 속도: **50ms** (CPU) / **5ms** (GPU)
- 속도 향상: **100배 이상**

---

## 2. Threshold 최적화 필요
**문제**:
- Smilegate 공식 권장값(17.4%)은 **혐오 표현**에 최적화
- 게임 내 경미한 투덜거림("바보", "짜증나")을 놓침
- Recall이 87.9%로 낮아 약 12%의 욕설이 미탐지

**해결 과정**:
1. 실제 게임 음성 채팅 패턴 반영한 **71개 샘플** 수집
   - 정상 38개, 경미 15개, 강함 12개, 혐오 6개
2. Threshold 0.05 ~ 0.30 구간 성능 측정
3. **데이터 기반 최적값 도출**

**결과**:
```
Threshold 0.10 선정
- Recall: 87.9% → 97.0% (+9.1%p)
- FP(오제재): 1건 → 2건 (허용 가능 수준)
- "바보"(Score 0.165), "화나"(Score 0.127) 등 탐지 가능
```

---

## 3. 오분류 케이스 발견 및 분석
**발견한 케이스** (Threshold 0.1 기준):

| 텍스트 | 실제 | 예측 | Score | 원인 분석 |
|--------|------|------|-------|----------|
| "대박이다 이걸 피하네" | Clean | Mild | 0.206 | '피하다', '대박' 단어가 부정 맥락에서 학습 |
| "오른쪽으로 피하세요" | Clean | Mild | 0.104 | 게임 명령어인데 '피하다' 때문에 오탐 |
| "이거 게임이 너무 어렵잖아" | Negative | Clean | 0.056 | 단순 불만 표현이 낮은 점수로 나옴 |

**대응 방안**:
- 게임 특화 명령어("피하세요", "뛰세요" 등) 화이트리스트 고려
- 맥락 이해를 위한 문장 단위 분석 필요성 인식

# 💡 개발하며 깨달은 핵심 인사이트

## 1. 공식 권장값 ≠ 우리 서비스 최적값
**배경**: Smilegate unSmile 모델의 공식 threshold는 17.4%

**깨달은 점**:
- 공식 값은 **일반적인 혐오 표현** 탐지에 최적화되어 있음
- 우리 서비스는 **게임 채팅 환경**이므로 사용 패턴이 다름
- **독자적인 데이터 수집 및 분석 필수**

**결론**: 
> 모델 개발자의 권장값을 맹신하지 말고, 실제 서비스 데이터로 검증하고 조정해야 한다.

---

## 2. Precision vs Recall 트레이드오프
**Threshold별 변화 관찰**:
```
Threshold ↓ (0.174 → 0.10)
→ Recall ↑ (87.9% → 97.0%)  ✅ 좋음
→ Precision ↓ (96.7% → 94.1%)  ⚠️ 약간 하락
→ FP 증가 (1건 → 2건)
```

**깨달은 점**:
- **완벽한 모델은 없다** (Precision과 Recall은 트레이드오프)
- 서비스 특성에 따라 어느 쪽을 우선할지 결정 필요
- 게임 환경에서는 **욕설 미탐지(FN)가 오제재(FP)보다 더 치명적**
  - 이유: FN은 게임 분위기를 해치지만, FP는 유저 신뢰를 잃게 함

**결론**:
> 둘 다 높일 순 없으니, **비즈니스 우선순위**에 따라 선택해야 한다. 우리는 FP를 최소화하되 Recall도 확보하는 균형점(0.10)을 찾았다.

---

## 3. 싱글톤 패턴의 실질적 효과
**Before**: 매 요청마다 모델 로드
```python
def predict(text):
    model = load_model()  # 5~10초 소요
    return model.predict(text)
```

**After**: 서버 시작 시 1회만 로드
```python
_model = load_model()  # 서버 시작 시 1회

def predict(text):
    return _model.predict(text)  # ~50ms
```

**깨달은 점**:
- 이론상 알고 있던 패턴이 실제로 **100배 차이**를 만듦
- 메모리 트레이드오프: 400MB 상주 vs 매번 로드
- **실시간 서비스에서는 메모리를 희생하더라도 속도 우선**

**결론**:
> 디자인 패턴은 단순한 이론이 아니라, 실제 서비스 성능에 **치명적 영향**을 미친다.

---

## 4. CPU vs GPU 성능 차이의 실체
**측정 결과**:

| 작업 | CPU | GPU | 배속 |
|------|-----|-----|------|
| 단건 추론 | 50ms | 5ms | 10배 |
| 배치(32개) | 1,200ms | 30ms | 40배 |

**깨달은 점**:
- GPU는 **배치 처리**에서 진가를 발휘 (40배!)
- 단건 추론도 10배 빠르지만, 배치에서 차이가 극명
- CUDA 설치/설정이 어렵지만 **투자 대비 효과 확실**

**결론**:
> AI 서비스에서 GPU는 선택이 아닌 필수. 특히 다수 사용자 동시 처리 시 필수적이다.

---

## 5. 실제 데이터의 중요성
**초기 접근**: 임의로 만든 테스트 케이스 사용

**문제 발견**:
- "ㅋㅋㅋ", "ㅎㅎㅎ" 같은 채팅 용어는 실제 음성에 없음
- "피하세요", "뛰세요" 같은 게임 명령어 패턴 발견 안 됨

**개선**: 실제 게임 음성 채팅 패턴 반영한 구어체 데이터셋 구축

**깨달은 점**:
- **테스트 데이터가 실제와 다르면 의미 없는 수치**
- 형식적인 커버리지보다 **현실성이 중요**

**결론**:
> 좋은 모델보다 좋은 데이터가 먼저다. 실제 서비스 환경을 반영한 데이터셋이 핵심이다.
