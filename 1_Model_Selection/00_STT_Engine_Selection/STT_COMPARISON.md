# 🎙️ STT 엔진 선정 — 왜 런타임은 Web Speech API인가

게임 음성채팅에서 **욕설을 탐지**하려면 먼저 음성을 텍스트로 바꿔야 한다(STT). 이 폴더는 **실시간 게임 런타임에서 쓸 STT 엔진**을 고른 기록이다.

> **결론 먼저**
> - **런타임(브라우저) STT = Web Speech API** ✅ — 실시간·무인프라·한국어 욕설 인식 충분.
> - **오프라인 학습데이터 수집 STT = faster-whisper large-v3** (`../../0_Data_Collection/02_stt`) — 정확도 최우선.
>
> 즉 STT를 **두 작업으로 분리**했다. "실시간으로 텍스트만 빨리 뽑는" 런타임과 "느려도 정확해야 하는" 데이터 라벨링은 요구사항이 정반대라, 하나의 엔진으로 둘 다 하지 않는다.

---

## 1. 런타임 STT는 무엇을 요구하나

게임 안 STT는 그 자체가 목적이 아니라 **욕설탐지 모델의 입력(텍스트)** 을 만드는 수단이다. 그래서 요구사항이 분명하다.

| 요구 | 이유 |
| :--- | :--- |
| **저지연** | 발화 → 저주 스택 반영이 즉각적이어야 게임이 됨. 60FPS 프레임을 깨면 안 됨 |
| **무인프라·저비용** | 4인 멀티플레이 웹게임. 세션마다 GPU STT 서버를 띄우는 건 배포·비용상 비현실적 |
| **한국어 + 욕설 인식** | 입력이 욕설이므로 비속어를 **검열 없이 원문 그대로** 받아야 함 |
| **튜닝 깊이** | ❌ 중요하지 않음 — 텍스트만 나오면 됨. AI 역량은 *분류 모델*에서 증명 |

마지막 줄이 핵심이다. 이 프로젝트의 AI 난이도·기여는 **STT가 아니라 "그 텍스트를 욕설/clean으로 분류하는 모델(UnSmile fine-tuning)"** 에 있다. STT는 잘 만들어진 걸 실용적으로 가져다 쓰는 게 맞다.

---

## 2. 후보 3안 비교

| 항목 | Web Speech API (브라우저) | 로컬 Whisper (Transformers.js) | faster-whisper 서버 (FastAPI+CUDA) |
| :--- | :--- | :--- | :--- |
| 처리 위치 | ☁️ 브라우저→구글 | 🖥️ 브라우저 On-Device | 🚀 로컬 GPU 서버 |
| 지연 | ⚡ 실시간 스트리밍 | 🐢 3~5초+ (WASM) | ⚡ 0.2~0.5초 |
| 한국어 정확도 | ✅ 우수(욕설 원문 인식) | ⚠️ 낮음(tiny 한계) | ✅ 최상(large-v3) |
| 인프라/비용 | ✅ **없음** | ✅ 없음(대신 CPU 폭증) | ❌ 세션마다 GPU 필요 |
| 배포 난이도 | ✅ 코드 몇 줄 | ⚠️ 번들·성능 | ❌ 서버 운영 복잡 |
| 튜닝(VAD·빔서치) | ❌ 블랙박스 | ⚠️ 제한 | ✅ 자유 |

- **로컬 Whisper(WASM)**: 브라우저에서 CPU로 돌리니 3~5초씩 밀려 실시간 게임에 부적합. 탈락.
- **faster-whisper 서버**: 빠르고 정확하지만, **웹 멀티플레이에서 클라이언트별로 GPU 추론 서버를 붙이는 구조가 비현실적**(비용·확장성). 런타임 STT로는 과한 선택.
- **Web Speech API**: 브라우저 네이티브라 인프라 0, 실시간, 한국어·욕설 인식이 충분히 좋다 → **런타임 채택**.

## 3. Web Speech API의 trade-off — 알고도 받아들인 이유

| 단점 | 받아들인 근거 |
| :--- | :--- |
| **블랙박스**(VAD·빔서치 튜닝 불가) | 런타임 STT엔 그 튜닝이 필요 없음. 텍스트만 확보하면 됨 |
| **크롬 의존**(`webkitSpeechRecognition`) | 타깃이 데스크톱 크롬 웹게임이라 허용 범위 |
| **클라우드 전송**(구글) | 음성은 즉시 텍스트화되어 게임 로직으로만 흐름. 저장하지 않음 |
| **인식 흔들림**(run-on, 오탐) | 뒤단 욕설 분류 모델이 노이즈에 견디도록 **게임 STT 데이터로 fine-tuning** → 바로 이 약점을 모델이 흡수 |

> 결국 "STT의 약점"은 **분류 모델 fine-tuning**으로 덮고, STT 자체는 가장 싸고 빠른 걸 쓴다 — 역할 분담이 명확하다.

---

## 4. faster-whisper는 버린 게 아니다 — 데이터 수집으로 재배치

런타임에서 빠진 faster-whisper(large-v3)는 **오프라인 학습데이터 수집**에 그대로 쓴다([`../../0_Data_Collection/02_stt`](../../0_Data_Collection/02_stt)). 라벨링용 코퍼스는 느려도 **정확도가 생명**이라 GPU Whisper가 정답이다.

| 작업 | 엔진 | 우선순위 |
| :--- | :--- | :--- |
| **런타임**(게임 중 실시간) | Web Speech API | 속도·무인프라 |
| **데이터 수집**(오프라인 라벨링) | faster-whisper large-v3 | 정확도 |

## 5. 실제 동작 — 런타임 흐름 & 직접 테스트

```
[브라우저] Web Speech API  ──5초 배치──▶ [Spring] WS SPEECH_BATCH ──HTTP──▶ [FastAPI] /analyze/batch
 음성→텍스트                              texts[] 전달                       파인튜닝 UnSmile → 저주 스택
```

- 📂 **실측 로그**: [`web_speech_api/`](web_speech_api/) — 게임 오디오(`audio_1`)를 인식 간격 200/300/500ms로 돌린 원본. 비속어(시발·개새끼 등)도 검열 없이 인식됨을 확인.
- 🧪 **직접 테스트**: [`web_speech_api/test_web_speech.html`](web_speech_api/test_web_speech.html) 을 **크롬에서 열고** 마이크 권한을 허용하면, 한국어 실시간 인식·지연시간을 눈으로 확인할 수 있다(사용법은 옆 README).
