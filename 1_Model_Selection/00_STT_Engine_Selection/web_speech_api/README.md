# web_speech_api, 런타임 STT(Web Speech API) 재현 도구 & 정성 샘플

런타임에서 채택한 STT 엔진 **Google Web Speech API**(브라우저 `webkitSpeechRecognition`)를 **직접 돌려보는 도구**와, 그 **정성 출력 샘플**입니다. 선정 근거·리스크는 [`../STT_COMPARISON.md`](../STT_COMPARISON.md).

## 🧪 진짜 측정값은 여기서, `test_web_speech.html`

**크롬에서** 열고(파일 더블클릭) 마이크 허용 후 말해 보면:

- 한국어 **실시간 인식**(중간 interim / 확정 final)
- **첫 응답 지연(ms)** = 발화 시작→첫 중간결과(스트리밍 응답성, 보통 수백 ms) · 평균 문장 간격 · 단어 수
- 욕설이 **검열 없이 원문 인식**되는지

> 이게 이 폴더에서 **유일하게 재현 가능한 정량 지표**(지연·confidence)다. Chrome/Edge 전용, 로컬 파일로 바로 동작(마이크 필요).

## 📄 인터벌별 정성 샘플, "5초 배치" 설계용 실험 (⚠️ 정확도 지표 아님)

한 게임플레이 음성을 Web Speech로 받아본 **원본 출력**으로, **인식 결과를 얼마 간격으로 끊어(commit) 모을지**를 200/300/500ms로 바꿔가며 남긴 것입니다.

### 왜 인터벌로 나눠 봤나, 5초 배치 설계 때문
게임 런타임은 브라우저가 인식한 텍스트를 **5초마다 한 번 묶어** 서버로 보냅니다
(`Web Speech → 5초 배치 → Spring → FastAPI /analyze/batch → 저주 스택`).
그 5초 버퍼에 **Web Speech의 중간(interim) 결과를 얼마나 자주 끊어 담을지(commit 주기)** 가 실제 설계 변수라, 인터벌별로 출력을 받아 **응답성 ↔ 문장 완결성** 트레이드오프를 눈으로 본 **런타임 튜닝 실험**입니다.

| commit 주기 | 장점 | 단점 |
| :--- | :--- | :--- |
| **짧게**(200ms) | 욕설을 빨리 포착(응답성↑) | 문장이 **조각남** → 분류기가 문맥 없이 토막을 봄 |
| **길게**(500ms) | 문장이 **완결**돼 분류 문맥↑ | 포착이 느림(응답성↓) |
| **무throttle**(default) | 설정이 가장 단순함 | 중간결과가 **중복** 기록(같은 말 반복) |

→ "5초 배치 안에서 어느 주기로 끊어 담아야 응답성과 완결성이 균형인가"를 보기 위한 실험. 출력 형태가 실제로 다음처럼 갈립니다(게임 오디오 1편):

| 파일 | 줄 수 | 단어 수 | 형태 |
| :--- | ---: | ---: | :--- |
| `webspeech_sample_default.txt` | 30 | 896 | interim **중복** 많음 |
| `webspeech_sample_200ms.txt` | 148 | 690 | 자주 끊겨 **조각** 많음 |
| `webspeech_sample_300ms.txt` | 54 | 679 | 중간 |
| `webspeech_sample_500ms.txt` | 14 | 556 | 드물게 끊겨 **길게 이어짐**(run-on) |

### 이 샘플이 보여주는 것 / 아닌 것 (정직하게)
- ✅ **보여주는 것**: Web Speech가 한국어 구어체 + **욕설(시발/개새끼/좆됐다 등)을 검열 없이** 받아적는다 → 욕설탐지 입력으로 적합하다는 **정성 증거**.
- ✅ **인터벌 트레이드오프**: 끊는 주기에 따른 응답성↔완결성 차이(위 표) → 5초 배치 설계 근거.
- ❌ **정확도 지표 아님**: 정답(ground-truth) 전사가 없어 WER/정확도는 못 잰다. 인터벌 차이도 엔진 정확도가 아니라 **chunking 형태**일 뿐.
- ❌ **파이프라인 audio_1과 무관**: 이 음성은 **좀비 서바이벌 게임** 플레이로, `02_stt`의 audio_1(**피코파크**)과 **다른 영상**이다 → train/serve 비교(같은 음성 페어)엔 못 씀.

## 한계와 다음 단계

Web Speech는 블랙박스(VAD·빔서치 튜닝 불가)지만 런타임 STT엔 그 튜닝이 불필요하다(텍스트만 확보). **학습=whisper / 런타임=web-speech** 차이가 있으나, 런타임은 **무BGM·단일화자(자기 마이크)** 라 web-speech에 유리한 조건이라 skew는 작다(학습데이터가 더 시끄러워 방향도 양성). 근거 [`../STT_COMPARISON.md` §4](../STT_COMPARISON.md). 정확도가 생명인 학습데이터 수집엔 faster-whisper를 따로 쓴다([`../../../0_Data_Collection/02_stt`](../../../0_Data_Collection/02_stt)).
