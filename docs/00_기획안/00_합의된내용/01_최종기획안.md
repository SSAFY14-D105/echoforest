# 🌲 메아리의 숲: 최종 기획안 (Agreed Plan)

팀원 간 합의된 핵심 게임 메커니즘과 시스템 아키텍처를 정의합니다.
이전의 논의된 내용보다 **본 문서의 내용을 최우선으로 적용**합니다.

---

## 1. 맵 컨셉 (Map Concept)
- **테마**: **메이플스토리 '인내의 숲' 스타일**.
- **특징**: 고난이도 점프킹류 플랫포머.
- **목표**: 각종 방해 공작(저주)을 뚫고 1탄(Stage 1) 끝까지 도달하기.

---

## 2. 🔮 저주 시스템 (Curse System) - **핵심**

### 2.1. 공통 저주 스택 (Shared Curse Gage)
- **작동 원리**: 팀원 전체가 공유하는 하나의 '저주 게이지'.
- **상승 조건**: 플레이어의 욕설/비속어 단계(Level 1~3)에 따라 차등 상승.
    - **Level 1 (가벼운 비속어)**: 스택 조금 상승.
    - **Level 2 (심한 욕설)**: 스택 중간 상승.
    - **Level 3 (금기어)**: 스택 대폭 상승 (즉시 발동 위험).
- **발동**: 게이지 MAX 도달 시 **팀원 중 1명에게 랜덤으로 저주**가 걸림.

### 2.2. 저주 종류 (Curse Types)
랜덤으로 걸리는 저주 3가지와 패시브 형태의 패널티 1가지로 구성됩니다.

| 구분 | 이름 | 효과 | 지속시간 |
|---|---|---|---|
| **랜덤 1** | **🔥 발화 (Burn)** | 5초 동안 불타오르며 사망 (타임어택, 즉시 리트라이). | 5초 |
| **랜덤 2** | **🦍 거대화 (Giant)** | 몸집이 커지고 이동 속도가 느려짐 (피격 판정 증가). | 일정 시간 |
| **랜덤 3** | **👽 반전 (Reverse)** | 좌우 방향키 조작이 반대로 바뀜. | 일정 시간 |
| **패시브** | **🤐 침묵 (Silence)** | 말을 안 하면(음성 입력 X) 캐릭터가 점점 느려지다 결국 **멈춤**. | 상시 |

## 3. ⚙️ 시스템 아키텍처 (System Architecture)

음성 데이터 흐름과 서버 간 통신 구조입니다.

### 3.1. 데이터 흐름 (Data Flow)
1.  **Frontend (Game Client)**: 
    - Web Speech API (STT) 등을 이용해 음성을 텍스트로 1차 변환.
    - 텍스트 데이터를 **게임 서버(Backend)**로 전송.
2.  **Game Server (Spring/Node)**:
    - 받은 텍스트를 **AI 서버(FastAPI)**로 분석 요청 (API Call).
3.  **AI Server (FastAPI)**:
    - **Unsmile 모델**을 통해 비속어 레벨(Lv 1~3) 판별.
    - 분석 결과(Level)를 게임 서버로 반환.
4.  **Game Server**:
    - 받은 Level에 따라 **Redis**에 저장된 '공통 저주 스택' 업데이트.
    - 스택이 꽉 찼을 경우, WebSocket을 통해 클라이언트에 **"저주 발동" 이벤트 브로드캐스트**.

### 3.2. 기술 스택
- **DB**: Redis (실시간 스택 관리, 빠른 R/W).
- **Communication**: WebSocket (실시간 게임 동기화 및 저주 알림).
