# 프로젝트 생태계와 네트워크 기초 이해 가이드

이 문서는 '저주 모험' 프로젝트의 전체 구동 원리부터 네트워크 인프라, 그리고 개발 도구의 진화에 이르기까지 핵심적인 개념들을 정리한 가이드입니다.

---

## 1단계: 프로젝트 생태계와 Nginx의 정체
**주제: '저주 모험' 프로젝트의 구성 요소와 프록시 설정의 중요성**

### 🛠 핵심 기술 스택
우리 프로젝트는 다음과 같은 기술들이 유기적으로 결합되어 있습니다.
- **프론트엔드**: React, Phaser (게임 로직 및 UI)
- **백엔드**: Spring Boot (메인 로직 및 데이터 관리)
- **AI 서버**: FastAPI (음성 및 감정 분석)
- **캐시**: Redis (빠른 데이터 접근)
- **화상**: LiveKit (실시간 통신)
- **대문**: Nginx (리버스 프록시 및 로드 밸런싱)

### 🚪 프록시(Nginx)의 역할
Nginx는 외부 요청을 각 서버로 배달하는 **'검문소'** 역할을 합니다.
- **중요성**: Nginx 설정이 잘못되면(WebSocket 업그레이드 누락, 헤더 유실 등) 프론트엔드에서만 로직이 돌아가고 데이터가 서버로 전달되지 않는 기형적인 버그가 발생할 수 있습니다.
- **Local vs EC2**: `localhost:5173`은 개인용 연습장이라면, `EC2 IP`는 전 세계가 보는 진짜 전시장입니다.

## 2단계: AI 개발 도구의 진화 (MCP & Context 7)
**주제: 안티그래비티 IDE에서 클로드/제미나이와 협업하는 법**

### 🧠 컨텍스트 7 + MCP: "뇌와 손의 완벽한 조화"
컨텍스트 7이 없으면 MCP는 눈을 가리고 수술하는 의사와 같습니다. 두 도구가 어떻게 협업하는지 그 시너지를 정리했습니다.

1. **컨텍스트 7 (사령탑/뇌)**
   - **하는 일**: 프로젝트 코드 전체($100\%$ 인덱싱)와 LiveKit, Phaser 공식 문서를 학습합니다.
   - **강점**: "이 버그는 LiveKit의 연결 방식과 Spring Boot의 세션 관리가 충돌해서 발생한 거야"라고 원인을 정확히 짚어줍니다.

2. **MCP (실행 도구/손)**
   - **하는 일**: 컨텍스트 7이 지목한 파일을 직접 수정하고, 실제 DB/Redis의 실시간 값을 가져옵니다.
   - **강점**: "방금 컨텍스트 7이 말한 대로 DB를 확인해보니 진짜 데이터가 꼬여 있네, 내가 바로 고칠게"라고 실천합니다.

## 3단계: 인프라와 보안의 열쇠 (SSH & SSL)
**주제: AWS EC2 서버 접속과 사용자 보안 가이드**

### 🔑 보안 구성 요소
- **SSH (.pem)**: 관리자 전용 뒷문 열쇠입니다. 터미널을 통해 원격 컴퓨터(EC2)를 직접 조작할 때 사용합니다.
- **SSL (HTTPS)**: 사용자 전용 정문 보안 장치입니다. 브라우저에서 카메라/마이크(WebRTC) 권한을 획득하기 위해 반드시 필요합니다.

### 🛡 인프라 관리
- **포트 제어**: 80(HTTP), 443(HTTPS), 22(SSH) 등 용도에 맞게 포트를 관리하고 불필요한 문은 닫아두는 것이 보안의 기본입니다.
- **자동 배포(Jenkins)**: 코드를 EC2로 옮겨주는 자동화된 트럭과 같은 역할을 수행합니다.

## 4단계: 네트워크의 마법 (포트, 5-Tuple, NAT)
**주제: 통신 원리와 보안 경계의 이해**

### 🌐 Inbound vs Outbound
- **내 컴퓨터**: 대문은 잠그지만(Inbound 차단), 내가 먼저 서버에 전화를 거는 것(Outbound)은 허용됩니다.
- **카톡의 원리**: 앱이 꺼져 있어도 푸시 서버와 맺어둔 '끈질긴 연결' 덕분에 메시지 수신이 가능합니다.

### 🧬 통신의 고유성 (5-Tuple)
IP와 Port 등 5개 요소의 조합 덕분에 수억 명이 동시에 접속해도 데이터가 섞이지 않고 정확한 목적지를 찾아갑니다.

### 🏠 NAT (공유기의 마법)
같은 공간에서 여러 명이 접속해도 공유기가 포트 번호를 실시간으로 바꿔주어(NAT) 데이터 중복을 방지합니다.

---

## 5단계: 데이터 무결성과 소프트웨어 버그
**주제: 데이터 혼선 사례의 진짜 원인 파악**

### 🔍 네트워크 vs 소프트웨어
데이터가 섞이거나 타인의 정보가 보이는 보안 사고는 통로(네트워크)의 문제보다는 주로 다음과 같은 **소프트웨어적 실수**에 기인합니다.
- 서버 캐시(Cache) 처리 오류
- 세션(Session) 관리 미흡
- DB 쿼리 로직의 허점

### 💡 MCP 활용의 본질
우리가 MCP를 통해 서버 데이터를 실시간으로 감시하려는 이유는 바로 이러한 **'로직의 실수'**를 빠르게 잡아내어 데이터 무결성을 유지하기 위함입니다.

## 🚀 컨텍스트 7을 포함한 MCP 실행 4단계 (최종판)

### [1단계] 지식 인덱싱 (Context 7 활성화)
- **작업**: 안티그래비티 IDE에서 프로젝트 폴더 전체와 LiveKit 공식 문서 URL을 컨텍스트 7에 학습시킵니다.
- **목표**: AI가 '저주 모험'의 모든 코드 구조와 외부 라이브러리 사용법을 마스터하게 합니다.

### [2단계] 보안 통로 확보 (Security Setup)
- **작업**: MySQL Read-Only 계정을 생성하고, AWS 보안 그룹에서 필요한 포트(80, 443, 10000-20000 등)를 확인합니다.
- **목표**: AI가 안전하게 데이터를 '조회'만 할 수 있도록 울타리를 칩니다.

### [3단계] MCP 서버 연결 (Connectivity)
- **작업**: IDE 설정에서 Filesystem, MySQL, Redis, Brave Search 서버를 연결합니다.
- **목표**: AI의 '손'이 실제 서버와 파일 시스템에 닿게 합니다.

### [4단계] 통합 디버깅 시작 (Full-Loop Debugging)
- **질문 예시**: "[Context 7] LiveKit 문서를 참고해서 지금 우리 프로젝트의 Nginx 설정이 WebRTC 통신에 맞는지 분석하고, nginx.conf를 수정해줘. 수정 후에는 DB에서 세션이 정상 저장되는지 확인해줘."

## ⚠️ 주의사항 (보안 및 최신성)

1. **인덱싱 범위 조절**: 비밀번호가 담긴 `.env` 파일이나 `.pem` 키가 들어있는 폴더는 인덱싱 범위에서 제외하세요. 컨텍스트 7이 이 내용을 학습해서 답변에 노출할 위험이 있습니다.
2. **최신성 유지**: 코드가 크게 바뀌거나 라이브러리를 업데이트했다면, 컨텍스트 7의 인덱싱을 **새로고침**해야 합니다. 옛날 지도를 보고 길을 찾으면 엉뚱한 코드를 수정할 수 있습니다.
3. **MCP 절제**: 너무 많은 MCP 활성화는 토큰 낭비와 도구 혼선을 야기하므로 필요한 것만 켜야 합니다.
