# Git Worktree 설정 및 관리 가이드

이 문서는 프로젝트의 다중 환경(Frontend, Backend, Docs 등)을 효율적으로 관리하기 위한 Git Worktree 설정 방법과 주의사항을 정리한 가이드입니다.

---

## 1. 워크트리 생성 명령어

루트 디렉토리에서 아래 명령어를 사용하여 상위 디렉토리에 새로운 환경을 구성합니다.

### A. 기존 브랜치를 새 워크트리로 연결할 때
```bash
# ✅ 올바른 순서: git worktree add <경로> <브랜치명>
git worktree add ../dev-docs existing-branch-name
```

### B. 새 브랜치를 생성하며 워크트리를 만들 때
```bash
# ✅ 올바른 순서: git worktree add -b <새브랜치명> <경로>
git worktree add -b dev-docs ../dev-docs
```

> [!CAUTION]
> **주의**: `git add worktree`가 아니라 **`git worktree add`** 순서여야 합니다!
> `git add`로 시작하면 Git이 경로에 있는 파일을 저장소에 추가(Staging)하려고 하기 때문에 "outside repository" 에러가 발생합니다.

> [!NOTE]
> 위 명령어에서 `../dev-docs`는 생성될 **폴더의 이름과 경로**를 의미하고, `-b dev-docs`는 새로 만들 **브랜치의 이름**을 의미합니다.

---

## 2. 명령어 구문 상세 설명

명령어의 각 인자가 무엇을 결정하는지 명확히 구분해야 합니다.

*   **`<경로>` (`../dev-docs`)**: 실제로 내 컴퓨터에 만들어질 **폴더의 위치와 이름**입니다.
*   **`<브랜치명>`**: 해당 폴더에 연결해서 작업할 **Git 브랜치**입니다.
*   **`-b` 옵션**: 브랜치가 아직 없을 때, 새로운 브랜치를 만들면서 동시에 워크트리 폴더도 생성하라는 의미입니다.

워크트리는 메인 저장소의 `.git` 디렉토리와 강력하게 연결되어 있으므로 다음 사항을 반드시 숙지해야 합니다.

### ① 폴더 이름 및 경로 변경 금지
*   **이유**: 메인 저장소의 `.git` 내부에는 워크트리의 **절대 경로**가 기록됩니다. 탐색기에서 임의로 이름을 바꾸거나 이동하면 연결이 깨집니다.
*   **해결책**: 경로 변경이 필요한 경우 명령어를 사용하세요.
    ```bash
    git worktree move <기존경로> <새경로>
    ```

### ② 동일 브랜치 중복 체크아웃 불가
*   **이유**: Git은 데이터 무결성을 위해 한 브랜치를 동시에 두 곳 이상의 워크트리에서 체크아웃하는 것을 금지합니다.
*   **해결책**: 각 워크트리는 고유한 브랜치를 담당해야 합니다.

### ③ 워크트리 삭제 시 정석 방법 준수
*   **이유**: 폴더만 강제 삭제하면 메인 저장소는 여전히 해당 브랜치가 사용 중인 것으로 인식하여 잠금 상태가 유지됩니다.
*   **해결책**: 아래 명령어로 삭제하는 것이 안전합니다.
    ```bash
    git worktree remove <워크트리경로>
    ```
    *만약 폴더를 이미 지웠다면 `git worktree prune`으로 정리하세요.*

### ④ 독립적인 종속성 관리
*   각 워크트리는 물리적으로 분리된 폴더이므로, `npm install`, `build` 등은 해당 폴더 내에서 각각 수행해야 합니다.

### ⑤ 브랜치 동기화 (Pull/Fetch) 주의사항
*   **Fetch**: 어느 워크트리 폴더에서든 `git fetch`를 실행하면 메인 저장소와 연결된 모든 원격 정보가 업데이트됩니다.
*   **Pull**: `git pull`은 **현재 폴더에 체크아웃된 브랜치만** 원격의 최신 상태로 병합합니다.
    *   **주의**: `dev-frontend` 폴더에서 `pull`을 실행했다고 해서 `dev-backend`나 `dev-docs` 폴더의 브랜치가 자동으로 업데이트되지 않습니다. 각 워크트리에서 최신 코드가 필요하다면 해당 폴더로 이동하여 각각 `pull`을 수행해야 합니다.

### ⑥ 워크트리 목록 확인
*   현재 내 PC에 어떤 워크트리들이 어디에 연결되어 있는지 확인하려면 아래 명령어를 사용하세요.
    ```bash
    git worktree list
    ```

## 3. 추천 디렉토리 구조

```text
/Project_Root (상위 폴더)
  ├── 01_공통프로젝트 (Main 저장소 - dev-frontend 중심)
  ├── dev-backend (Worktree - backend 브랜치)
  └── dev-docs (Worktree - docs 브랜치)
```
