## 1단계: 사령탑 세우기 (Context 7 - 지식과 지도)

**목표**: AI가 당신의 프로젝트를 '진짜로' 이해하게 만드는 단계입니다.

### 🧠 학습 원칙 (토큰 절약)
AI가 이미 아는 것(React, Spring Boot 기본)은 생략하고, **'우리 집만의 사정'**만 가르칩니다.

### 📁 인덱싱 대상
| 대상 | 설명 | 예시 |
|------|------|------|
| **소스 코드 전체** | Git Worktree 내의 모든 파일 | `echoforest-frontend/`, `echoforest-backend/` |
| **공식 문서 URL** | LiveKit, MediaPipe 최신 문서 | `docs.livekit.io`, `mediapipe.dev` |
| **프로젝트 문서** | 우리만의 규칙과 구조 | `04_S14PD105_docs/` |

### ⚙️ 컨텍스트 7 활성화 방법 (Antigravity IDE)
```
1. 프로젝트 폴더를 Workspace로 열기
2. 좌측 파일 탐색기에서 인덱싱 상태 확인 (자동 진행)
3. 외부 문서 참조가 필요한 경우:
   - 프롬프트에 "LiveKit 공식 문서 참고해서..." 형태로 요청
   - AI가 필요시 web search를 통해 최신 정보 조회
```

### 🚨 인덱싱 제외 대상 (보안)

**✅ 방법 1: `.gitignore`로 충분! (대부분의 경우)**
```
.gitignore에 있는 파일들은 자동으로 AI 인덱싱에서도 제외됩니다!
별도 설정 없이 .gitignore만 잘 관리하면 됩니다.
```

**⚙️ 방법 2: `.geminiignore`는 고급 옵션 (필요할 때만)**
```bash
# 언제 필요한가?
# 1. Git에는 올려야 하지만, AI에게는 안 보여주고 싶을 때
#    예: 대용량 테스트 데이터, 레거시 코드
# 2. 개인적으로만 제외하고 싶을 때

# 프로젝트 루트에 .geminiignore 파일 생성 (.gitignore와 같은 문법)
legacy_code/
test_data/
*.log
```

> ⚠️ **주의**: 컨텍스트 7이 민감 정보를 학습하면 답변에 노출될 위험이 있습니다!

```
┌─────────────────────────────────────────────────────────────┐
│  .pem 파일 = EC2 서버의 "집 열쇠" 🔑                         │
│                                                              │
│  ❌ Git에 올리면?                                            │
│     → 전 세계 누구나 우리 서버에 접속 가능 → 해킹당함       │

│     → 인프라 담당자만 안전하게 보관                          │
│     → 필요한 팀원에게만 개별 전달 (카톡, USB 등)            │
│     → 절대 Git에 올리지 않음                                 │
│                                                              │
│  💡 .gitignore에 *.pem 추가한 이유:                          │
│     → "실수로 올리는 것 방지" 안전장치                       │
└─────────────────────────────────────────────────────────────┘
```

## 2단계: 손과 발 장착하기 (MCP - 실전 도구)

**목표**: AI가 실제로 데이터를 확인하고 코드를 고치게 만드는 물리적 통로입니다.

### 🔧 MCP 역할 매트릭스

| MCP 종류 | 상세 역할 | 설정 시 필수 정보 | 위험도 |
|----------|----------|-------------------|--------|
| **Filesystem** | 코드 읽기/쓰기, 설정 파일 수정 | 프로젝트 로컬 절대 경로 | 🟡 중 |
| **MySQL** | DB 플레이어 정보/로그 조회 | EC2 IP, Read-Only 계정, DB명 | 🔴 고 |
| **Redis** | 실시간 위치 좌표($x, y$) 감시 | `redis://[EC2_IP]:6379` | 🟡 중 |
| **Brave Search** | 최신 에러 사례 및 기술 검색 | Brave Search API Key | 🟢 저 |

### � MCP 설치 가이드 (처음 사용자용)

> 💡 **MCP란?** Model Context Protocol의 약자로, AI가 외부 도구(파일시스템, DB 등)에 접근할 수 있게 해주는 표준 프로토콜입니다.

#### Step 1: Antigravity IDE 설정 파일 열기
```
1. Antigravity IDE 좌측 하단 ⚙️ 아이콘 클릭
2. Settings → MCP Servers 메뉴 선택
3. "Add Server" 버튼 클릭
```

#### Step 2: MCP 서버 추가
```json
// Filesystem MCP (기본 - 코드 읽기/쓰기)
{
  "name": "filesystem",
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem", "프로젝트_경로"]
}
```

#### Step 3: 연결 확인
```
- 좌측 하단 MCP 아이콘에 녹색 점이 표시되면 연결 성공
- AI에게 "현재 연결된 MCP 서버 목록을 알려줘" 라고 질문
```

#### 🎯 추천 MCP 우선순위
| 순위 | MCP | 이유 | 난이도 |
|------|-----|------|--------|
| 1️⃣ | Filesystem | 코드 편집 필수 | ⭐ 쉬움 |
| 2️⃣ | Web Search | 에러 검색 유용 | ⭐ 쉬움 |
| 3️⃣ | Redis | 실시간 데이터 확인 | ⭐⭐ 보통 |
| 4️⃣ | MySQL | DB 조회 (인프라팀 협조 필요) | ⭐⭐⭐ 어려움 |

## 3단계: 보안 성벽 쌓기 (안전 장치)

**목표**: AI에게 권한을 주되, 내 서버를 망가뜨리지 못하게 막는 **3중 방어선**입니다.

### 🛡️ 방어선 1: DB 권한 격리

```sql
-- MySQL Read-Only 계정 생성 (인프라팀 실행)
CREATE USER 'readonly_ai'@'%' IDENTIFIED BY 'secure_password_here';
GRANT SELECT ON echoforest_db.* TO 'readonly_ai'@'%';
FLUSH PRIVILEGES;

-- 권한 확인
SHOW GRANTS FOR 'readonly_ai'@'%';
```

> ✅ **핵심**: `SELECT` 권한만 부여하여 AI가 데이터를 삭제/수정하는 사고를 원천 차단

### 🛡️ 방어선 2: 실행 전 승인 (IDE 설정)

```
📍 설정 경로:
1. Antigravity 좌측 하단 ⚙️ 아이콘 클릭
2. Settings → Features → Tools
3. "Require confirmation for..." 옵션들 확인

💡 권장 설정:
- ✅ Require confirmation for file writes
- ✅ Require confirmation for command execution
- ✅ Require confirmation for database queries
```

> AI가 "이 SQL을 실행할까요?"라고 물을 때 **당신이 최종 승인**을 해야 합니다.

### 🛡️ 방어선 3: 인프라 보안 (SSH/SSL)

| 구분 | 역할 | 소유자 | 주의사항 |
|------|------|--------|----------|
| **SSH (.pem)** | 관리자 전용 뒷문 열쇠 | 인프라 담당자만 | ❌ AI에게 절대 텍스트로 알려주지 마세요 |
| **SSL (HTTPS)** | 사용자 전용 정문 보안 | Nginx 설정 | ✅ LiveKit WebRTC 필수 요구사항 |

### 🔐 토큰/비밀번호 관리

```json
// ❌ 잘못된 예시 - 하드코딩
{
  "password": "my_secret_password"
}

// ✅ 올바른 예시 - 환경변수 사용
{
  "password": "${MYSQL_READONLY_PASSWORD}"
```

## 4단계: 네트워크 흐름 이해 (디버깅의 기초)

**목표**: 버그가 생겼을 때 "어디가 막혔나"를 판단하는 기준입니다.

### 🌐 Inbound vs Outbound

```
┌─────────────────────────────────────────────────────────────┐
│  [내 컴퓨터]                    [서버 (EC2)]                 │
│                                                              │
│   Inbound ←──────────── ❌ 차단 ────────────── 외부 요청     │
│   (들어오는 연결)                                            │
│                                                              │
│   Outbound ─────────── ✅ 허용 ──────────────→ 서버 요청    │
│   (나가는 연결)                                              │
└─────────────────────────────────────────────────────────────┘

💡 카톡의 원리: 앱이 꺼져 있어도 푸시 서버와 맺어둔 
   '끊기지 않는 연결(Persistent Connection)' 덕분에 메시지 수신 가능
```

### 🧬 5-Tuple 식별자

데이터가 섞이지 않는 이유: 5개 요소의 **유니크 조합**

| 요소 | 예시 |
|------|------|
| Source IP | `192.168.0.15` |
| Source Port | `52431` |
| Dest IP | `3.35.xxx.xxx` (EC2) |
| Dest Port | `443` |
| Protocol | `TCP` |

### 🏠 NAT (공유기의 마법)

```
같은 카페에서 3명이 동시 접속해도:
- 사용자A: 192.168.0.10:54321 → 외부IP:10001
- 사용자B: 192.168.0.11:54321 → 외부IP:10002
- 사용자C: 192.168.0.12:54321 → 외부IP:10003

→ 공유기가 포트 번호를 실시간으로 변환(NAT)하여 데이터 중복 방지
```

### 🔍 데이터 혼선의 진짜 원인

**"남의 메시지가 보여요!"** 같은 사고는 네트워크(통로) 문제가 아닙니다.

| 실제 원인 | 설명 | MCP로 확인 방법 |
|-----------|------|-----------------|
| **서버 캐시 오류** | 이전 사용자 데이터가 캐시에 남음 | Redis MCP로 캐시 키 확인 |
| **세션 관리 미흡** | 세션 ID 중복 또는 만료 처리 누락 | MySQL MCP로 세션 테이블 조회 |
| **DB 쿼리 허점** | WHERE 절 누락, 잘못된 JOIN | MySQL MCP로 쿼리 결과 검증 |

## 5단계: 통합 실전 워크플로우 (Daily Routine)

```
┌─────────────────────────────────────────────────────────────┐
│ [0단계] 사전 모니터링                                        │

                            ↓
┌─────────────────────────────────────────────────────────────┐

│           로직상 허점이 있는지 찾아줘"                       │
│                                                              │
│ AI 응답 예시: "Player.ts의 updatePosition() 함수에서        │
│               throttling 없이 매 프레임 전송하고 있어요"    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ [2단계] MCP 가동                                             │
│ 프롬프트: "분석 결과를 바탕으로 Redis MCP를 써서            │
│           현재 서버에 저장된 실제 좌표값을 읽어와 줘"       │
│                                                              │
│ AI 동작: Redis에서 player:1234:position 키 조회             │
│ 결과: { x: 150, y: 200, timestamp: 1706234567890 }          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ [3단계] 비교 분석                                            │
│ 프롬프트: "서버 값(150,200)과 프론트 값(145,198)이 다른데,  │
│           이 차이가 발생하는 원인을 분석해줘"               │
│                                                              │
│ AI 분석: "네트워크 지연 + 클라이언트 예측(CSP) 미적용"     │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ [4단계] 최종 수정                                            │
│ 프롬프트: "Filesystem MCP로 Player.ts에 throttling 로직과  │
│           CSP(Client-Side Prediction)를 추가해줘"           │
│                                                              │
│ ⚠️ 승인 요청: "Player.ts를 수정하시겠습니까?" → [Yes]      │
└─────────────────────────────────────────────────────────────┘
```

### 🎯 자주 쓰는 프롬프트 템플릿

```markdown

## 설정 수정 요청
```

## 🛠️ 최종 설정 파일 예시

### 🧠 Context 7 vs MCP - 헷갈리지 마세요!

```
┌─────────────────────────────────────────────────────────────┐
│  Context 7 (IDE 자체 기능)                                    │
│  → Workspace를 열면 자동 활성화                              │
│  → 코드를 읽고 이해하는 능력                                  │
│  → 별도 설정 필요 없음!                                      │
├─────────────────────────────────────────────────────────────┤
│  MCP (외부 도구 연결)                                         │
│  → mcp_config.json에서 설정                                 │
│  → AI가 DB, Redis 등에 접근하는 통로                          │
│  → 필요한 MCP만 설치/활성화                                    │
└─────────────────────────────────────────────────────────────┘
```

### 📁 MCP 설정 파일 위치

**실제 파일 경로:**
```
C:\Users\{USERNAME}\.gemini\antigravity\mcp_config.json
```

> ✅ **안심하세요**: 이 파일은 **사용자 홈 폴더**에 있어서 프로젝트 Git에 포함되지 않습니다!
> 따라서 `.gitignore`에 추가할 필요가 없습니다.

## 💰 토큰 관리 전략 (비용 최적화)

### 🚨 왜 토큰 관리가 중요한가?

```
┌─────────────────────────────────────────────────────────────┐
│  MCP 서버가 많을수록 → AI가 매번 "도구 목록"을 읽음           │
│                     → 각 도구의 설명문이 토큰을 소비          │
│                     → 실제 질문 전에 이미 토큰 낭비!          │
└─────────────────────────────────────────────────────────────┘

예시: MCP 10개 활성화 시
- 도구 목록만 읽는데 ~2,000 토큰 소비
- 대화 1회당 숨겨진 비용 발생
- 월말에 생각보다 높은 비용 청구 😱
```

### ⚡ 토큰 절약 4원칙

#### 원칙 1: 필요한 MCP만 켜기
```
❌ 나쁜 예: 모든 MCP를 항상 켜두기
✅ 좋은 예: 작업별로 필요한 MCP만 활성화

📍 작업별 추천 MCP 조합:
- 코드 작성: Filesystem만
- 버그 분석: Filesystem + Web Search
- DB 디버깅: Filesystem + MySQL + Redis
- 일반 질문: MCP 없이도 가능!
```

#### 원칙 2: 큰 파일 직접 전송 금지
```
❌ 나쁜 예: "이 JSON 파일 전체를 분석해줘" (5000줄)
✅ 좋은 예: "package.json의 dependencies 부분만 봐줘"

💡 팁: AI에게 "필요한 부분만 읽어줘"라고 명시
```

#### 원칙 3: 반복 질문 피하기
```
❌ 나쁜 예: 매번 "프로젝트 구조 설명해줘"
✅ 좋은 예: 한 번 받은 설명은 문서로 저장 (이 가이드처럼!)

💡 팁: 자주 묻는 질문은 CLAUDE.md에 정리
```

#### 원칙 4: 컨텍스트 초기화 활용
```
📍 새 대화 시작하는 것이 좋은 경우:
- 완전히 다른 주제로 넘어갈 때
- 이전 대화가 길어져서 AI가 헷갈릴 때
- 민감한 정보가 이전 대화에 포함되었을 때

📍 대화 이어가는 것이 좋은 경우:
- 같은 버그를 계속 추적할 때
- 이전 분석 결과를 참고해야 할 때
```

### 📊 토큰 사용량 모니터링

```
📍 확인 방법:
1. Antigravity IDE 우측 상단의 사용량 표시 확인
2. 대화가 길어지면 "현재 토큰 사용량" 질문
3. 월간 리포트로 패턴 분석

📍 경고 신호:
- 한 대화에서 50,000+ 토큰 사용 → 새 대화 시작 고려
- 같은 질문 반복 → 문서화 필요
- MCP 오류로 재시도 반복 → 설정 점검 필요
```

### 🎯 실전 예시: 효율적인 질문 vs 비효율적인 질문

| 상황 | ❌ 비효율적 | ✅ 효율적 |
|------|------------|----------|
| 에러 해결 | "에러 났어" | "TypeError: xxx 에러가 Player.ts 23번 줄에서 발생" |
| 코드 분석 | "전체 분석해줘" | "updatePosition 함수만 봐줘" |
| 문서 찾기 | "LiveKit이 뭐야?" | "LiveKit Room 연결 코드 예시 보여줘" |
| DB 확인 | "모든 데이터 보여줘" | "player_id=1234인 레코드만 조회" |

### 🔒 보안 관련

- [ ] `.env` 파일이 `.gitignore`에 포함되어 있는가?
- [ ] `.pem` 키 파일이 인덱싱 범위에서 제외되었는가?

- [ ] MCP 설정 파일에 비밀번호가 하드코딩되어 있지 않은가?
