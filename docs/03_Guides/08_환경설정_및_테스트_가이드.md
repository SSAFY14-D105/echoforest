# 환경 설정 및 테스트 환경 구축 가이드

## 📌 개요

이 가이드는 로컬 도커 환경과 원격 서버 환경을 쉽게 전환하면서 테스트할 수 있는 방법을 설명합니다.

## 🎯 해결하는 문제

1. **로컬 도커 버그**: 복잡한 인증 시스템(LiveKit, AI 서버 등)이 얽혀있어 발생하는 버그
2. **환경 전환의 어려움**: 로컬 ↔ 원격 서버 전환 시 설정 파일 수정의 번거로움
3. **Git 충돌**: 공용 설정 파일을 수정하면서 발생하는 충돌

## 🔧 핵심 원칙

**✅ DO (해야 할 것)**
- 개인 설정 파일 사용: `docker-compose.override.yml`, `.env.local`
- `.gitignore`에 추가된 파일만 수정
- 환경 전환 스크립트 사용

**❌ DON'T (하지 말아야 할 것)**
- 공용 파일 직접 수정: `docker-compose.yml`, `.env` (백엔드 .env는 이미 gitignore 됨)
- 개인 설정을 Git에 커밋
- 팀원의 환경에 영향을 주는 변경

## 🚀 빠른 시작

### 방법 1: 대화형 스크립트 사용 (가장 쉬움) ⭐

#### 백엔드 환경 설정
```bash
cd 02_S14P11D105_backend/echoforest-backend
setup-env.bat
```

메뉴에서 선택:
- `1`: 로컬 도커 환경
- `2`: 원격 서버 연결 (서버 주소 입력)
- `3`: 현재 설정 확인

#### 프론트엔드 환경 설정
```bash
cd 01_S14P11D105_frontend/echoforest-frontend
setup-env.bat
```

### 방법 2: 수동 설정

#### 로컬 도커 환경

**백엔드:**
```yaml
# docker-compose.override.yml 생성
version: '3.8'

services:
  game-server:
    environment:
      - LIVEKIT_URL=http://livekit:7880
      - AI_MODEL_URL=http://host.docker.internal:8000
```

**프론트엔드:**
```bash
# .env.local 생성
VITE_API_BASE_URL=http://localhost:9001/api
VITE_LIVEKIT_URL=ws://localhost:7880
```

#### 원격 서버 연결

**백엔드:**
```yaml
# docker-compose.override.yml 생성
version: '3.8'

services:
  game-server:
    environment:
      - LIVEKIT_URL=ws://i14d105.p.ssafy.io:7880
      - AI_MODEL_URL=http://i14d105.p.ssafy.io:8000
      # 필요시 DB도 원격으로
      # - DB_URL=jdbc:mysql://i14d105.p.ssafy.io:3306/echoforest
```

**프론트엔드:**
```bash
# .env.local 생성
VITE_API_BASE_URL=http://i14d105.p.ssafy.io:9001/api
VITE_LIVEKIT_URL=ws://i14d105.p.ssafy.io:7880
```

## 📋 테스트 시나리오별 가이드

### 시나리오 1: 완전 로컬 테스트

모든 서비스를 로컬에서 실행합니다.

```bash
# 1. 백엔드 설정
cd 02_S14P11D105_backend/echoforest-backend
setup-env.bat  # 메뉴에서 1 선택

# 2. AI 서버 실행 (별도 터미널)
cd 03_S14P11D105_ai/echoforest-ai
python main.py  # 또는 적절한 실행 명령

# 3. 백엔드 실행
docker-compose up --build

# 4. 프론트엔드 설정 및 실행 (별도 터미널)
cd 01_S14P11D105_frontend/echoforest-frontend
setup-env.bat  # 메뉴에서 1 선택
npm run dev
```

**장점**: 모든 것을 직접 제어 가능
**단점**: 모든 서비스를 직접 실행해야 함

### 시나리오 2: 원격 서버 테스트

원격 서버의 안정적인 백엔드/LiveKit을 사용합니다.

```bash
# 1. 프론트엔드 설정
cd 01_S14P11D105_frontend/echoforest-frontend
setup-env.bat  # 메뉴에서 2 선택, 서버 주소 입력

# 2. 프론트엔드만 실행
npm run dev
```

**장점**: 
- 백엔드/LiveKit 인증 문제 없음
- 안정적인 테스트 환경
- 빠른 프론트엔드 개발

**단점**: 백엔드 수정사항 테스트 불가

### 시나리오 3: 하이브리드 (권장)

로컬 백엔드 + 원격 LiveKit/AI

```bash
# 1. 백엔드 설정
cd 02_S14P11D105_backend/echoforest-backend

# docker-compose.override.yml 수동 생성
version: '3.8'
services:
  game-server:
    environment:
      - LIVEKIT_URL=ws://i14d105.p.ssafy.io:7880  # 원격
      - AI_MODEL_URL=http://i14d105.p.ssafy.io:8000  # 원격
      - DB_URL=jdbc:mysql://mysql:3306/echoforest  # 로컬

# 2. 백엔드 실행
docker-compose up --build

# 3. 프론트엔드 설정 및 실행
cd 01_S14P11D105_frontend/echoforest-frontend
setup-env.bat  # 메뉴에서 1 선택 (localhost 백엔드)
npm run dev
```

**장점**: 
- 백엔드 개발 가능
- LiveKit/AI 서버 안정성 확보
- 최적의 개발 환경

## 🔍 문제 해결

### LiveKit 연결 실패

**증상**: "Failed to connect to LiveKit server"

**확인사항**:
```bash
# 1. LiveKit 서버 상태 확인
docker logs echoforest-livekit

# 2. 포트 확인
netstat -an | findstr 7880

# 3. 방화벽 확인 (Windows)
# Windows Defender 방화벽에서 7880 포트 허용
```

**해결책**:
```yaml
# 원격 LiveKit 사용
# docker-compose.override.yml
services:
  game-server:
    environment:
      - LIVEKIT_URL=ws://i14d105.p.ssafy.io:7880
```

### AI 서버 연결 실패

**증상**: "Connection refused to AI server"

**확인사항**:
```bash
# 1. AI 서버 실행 확인
curl http://localhost:8000/health

# 2. Docker에서 호스트 접근 확인
docker exec -it echoforest-server curl http://host.docker.internal:8000/health
```

**해결책**:
- AI 서버가 8000 포트에서 실행 중인지 확인
- 또는 원격 AI 서버 사용

### 방 입장 실패

**증상**: "Failed to join room"

**체크리스트**:
1. ✅ 백엔드가 정상 실행 중인가?
2. ✅ LiveKit 연결이 정상인가?
3. ✅ Redis 연결이 정상인가?
4. ✅ 인증 토큰이 정상 발급되는가?

**디버깅**:
```bash
# 백엔드 로그 확인
docker logs -f echoforest-server

# Redis 연결 확인
docker exec -it echoforest-redis redis-cli ping
# 응답: PONG

# LiveKit 로그 확인
docker logs -f echoforest-livekit

# 브라우저 개발자 도구 > 콘솔에서 WebSocket 연결 확인
```

### Docker Compose Override가 적용 안 됨

**증상**: 환경 변수가 변경되지 않음

**확인**:
```bash
# 1. 파일 이름 확인
# 정확히 'docker-compose.override.yml' 이어야 함

# 2. 파일 내용 확인
type docker-compose.override.yml

# 3. Docker Compose 재시작
docker-compose down
docker-compose up --build
```
