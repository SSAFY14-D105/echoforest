## 2. 데이터 전처리 및 수집 자동화 구현 (Python vs Browser)
### (1) Python `speech_recognition` vs Browser `Web Speech API` 괴리
현재 저는 `audio_transcriber_web.py` 파일에서 Python의 `speech_recognition` 라이브러리(`recognize_google`)를 사용해 유튜브 MP3 파일을 텍스트로 바꾸고 있습니다.
- **질문**: 
  - Python 코드(`sr.recognize_google`)로 수집한 STT 데이터가, 실제 서비스 환경인 **Chrome Browser `Web Speech API`**와 동일한 특성(오타율, 끊김 등)을 가진다고 볼 수 있나요? 
  - 혹시 Python 라이브러리는 파일 업로드 방식이고, 브라우저는 스트리밍 방식이라 결과 품질이 다르진 않나요? (만약 다르다면 학습 데이터로서의 가치가 떨어질까 걱정됩니다.)

### (2) 브라우저 자동화 (YouTube 재생 + STT 수집)
답변에서 "브라우저에서 유튜브를 재생하고 Web Speech API로 수집하라"는 뉘앙스의 내용을 본 것 같은데, 구현이 이해가 안 됩니다.
- **질문**:
  - Python Selenium 등으로 브라우저를 띄워서 유튜브를 틀고, 동시에 해당 브라우저 탭에서 JS로 Web Speech API를 켜서 캡처하라는 뜻인가요? 
  - 아니면 현재 방식(Python 라이브러리 사용)을 유지해도 충분한가요?

### (3) VAD Chunking 후 최소 길이 필터링
- **질문**: VAD로 자른 후 너무 짧은(예: 0.5초 미만) 오디오는 버리는 게 좋다고 하셨는데, **전체 데이터의 몇 % 정도 비중**으로 필터링 기준을 잡는 게 일반적인가요? (예: 1초 미만 삭제?)

## 3. Web Speech API 스타일의 노이즈 주입 (Data Augmentation)
### (1) 문장 끝 생략 vs 중간 생략
Web Speech API는 말소리가 작아지는 문장 끝부분을 놓치는 경우가 많다고 생각합니다.
- **질문**:
  - 학습 데이터를 만들 때 **모든 문장의 5% 정도를 랜덤하게 생략**하라고 하셨는데, **"문장의 마지막 단어"**를 생략하는 게 현실 고증에 맞을까요, 아니면 **"중간 단어"**를 생략해도 되나요?
  - 실제 STT 엔진 특성상 중간 단어가 빠지는 경우(발음 뭉개짐)도 빈번한가요?

## 4. 브라우저 성능 최적화 (Web Worker)
게임과 화상 채팅, STT가 동시에 돌아가니 CPU 병목으로 렉이 심합니다.
- **질문**:
  - **Web Worker**를 도입해서 STT 처리나 로직 연산을 메인 스레드에서 분리하면 렉 현상이 유의미하게 줄어들까요? (Web Speech API 자체가 메인 스레드 부하를 얼마나 주는지 궁금합니다.)

## 5. 모델 구조 및 학습 전략 (Unsmile + New Label)
### (1) Unsmile의 Base Model: BERT는 한국어 모델인가요?
- **질문**: Unsmile 공식 모델이 **BERT** 기반이라고 확인했는데, 이것은 `bert-base-multilingual-cased` 인가요, 아니면 한국어 전용으로 사전 학습된 다른 BERT 모델(예: `KlueBERT`)인가요? (해외 모델 기반이면 한국어 뉘앙스 처리가 약할까 우려됩니다.)

### (2) 라벨 수와 성능 재현 가능성
- **상황**: Unsmile 데이터셋은 10개(여성, 남성, 성소수자 등) 라벨 + Clean으로 구성된 것으로 알고 있습니다. 여기에 저희의 `팀 사기 저하`를 더하면 총 **11~12개 클래스**가 됩니다.
- **질문**:
  - Unsmile 가이드를 따라 학습하면, 배포된 Unsmile 모델만큼의 **높은 성능(F1 Score)**을 저희도 재현할 수 있을까요?
  - 라벨 수가 늘어나도 성능 유지가 가능할까요?

### (3) 데이터 불균형 (18,000 vs 1,000) 학습 비율
- **상황**: Unsmile 원본 데이터(약 18,000개) vs 저희가 라벨링할 데이터(약 700개 + 신조어 300개 = 1,000개). 비율이 **18:1** 정도로 차이가 큽니다.
- **질문**:
  - 이대로 다 섞어서 학습하면 모델이 저희 라벨(`팀 사기 저하`)을 거의 무시하지 않을까요?
  - 저희 데이터를 **Oversampling(복제)**해서 비율을 1:1이나 1:5 정도로 맞춰야 할까요, 아니면 그냥 놔둬도 될까요?
