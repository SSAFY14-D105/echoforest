## 1. 핵심 설계 결정 ⭐

### 긍정 vs 부정 처리 분리

| 구분 | 처리 방식 | 레이턴시 | 입력 방식 |
|------|----------|----------|----------|
| **긍정 (스킬)** | JS 키워드 매칭 | < 50ms | Push-to-Talk |
| **부정 (저주)** | AI 감정 분석 | 5~10초 OK | 상시 감지 |

```
긍정: "뽀뽀" 말하면 즉시 스킬 발동! (VAD 대기 없이)
부정: 욕설 감지 후 딜레이 있어도 OK (눈치 못 채게)
```

### Web Speech API 특성

- **중간 결과 (interim)**: 실시간 업데이트 → 긍정 키워드 즉시 감지 가능!
- **최종 결과 (final)**: VAD 청킹 후 확정 → 부정 발언 분석용

## 2. 데이터 관련 결정 사항

### 기존 데이터셋이 안 맞는 이유

| 문제 | 설명 |
|------|------|
| **초성체** | 텍스트 채팅은 "ㅅㅂ" → STT는 "씨발" 출력 |
| **도메인** | 영화 리뷰 ≠ 게임 음성 |
| **윤리** | 기존 모델은 욕설 학습 안 됨 |

### 데이터 수집 전략

```
유튜브 게임 VOD → 음성만 추출 → STT 변환 → 라벨링 → Fine-tuning
```

```bash
# 음성만 다운로드 (영상 없이!)
yt-dlp -x --audio-format mp3 "VIDEO_URL"
```

### 목표 데이터량

- 수집: 50~100시간 (~5GB 음성)
- 학습: 5,000~10,000개 문장

## 3. 모델 벤치마크 결과

| 모델 | 정확도 | 레이턴시 | 비고 |
|------|--------|----------|------|
| KoELECTRA Base | 50% | 8.9ms | 🏆 최고 정확도 |
| UnSmile | 50% | 7.9ms | ⚡ 최저 레이턴시, 혐오 특화 |
| Multilingual | 50% | 7.4ms | 다국어 |
| Korean Sentiment | 30% | 9.8ms | - |

> ⚠️ 정확도가 낮은 이유: 학습 데이터 ≠ 게임 음성 (Fine-tuning 필요)
