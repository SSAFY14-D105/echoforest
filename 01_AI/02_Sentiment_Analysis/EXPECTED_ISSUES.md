# 🚧 Expected Issues & Solutions

> 감정 분석 시스템 구현 시 예상되는 문제점과 해결책

---

## 1. Computational Overhead (연산 부담)

### 예상 문제

| 항목 | 상시 AI 방식 | 영향 |
|------|------------|------|
| CPU/GPU 사용량 | 초당 ~100회 추론 | 게임 프레임 영향 가능 |
| 메모리 사용량 | 모델 ~200MB 상주 | 브라우저 메모리 부담 |
| 추론 시간 | 7~12ms/회 | 누적 시 지연 |

### 해결책 (나중에 필요시)

- 키워드 필터로 AI 호출 횟수 감소
- 모델 양자화 (크기 50% 감소)
- Web Worker로 분리 처리

---

## 2. Multi-Player 환경 (4인 게임)

### 걱정: 4명이면 부담 4배?

**❌ 아니요!** 브라우저 기반이라 괜찮음.

```
[플레이어 A 브라우저] → 본인 음성만 처리
[플레이어 B 브라우저] → 본인 음성만 처리
[플레이어 C 브라우저] → 본인 음성만 처리
[플레이어 D 브라우저] → 본인 음성만 처리

각자 독립! 서버 부담 없음!
```

| 처리 위치 | 서버 부담 | 확장성 |
|----------|----------|--------|
| **브라우저 (현재)** | ✅ 없음 | ✅ 무제한 |
| 서버 | 🔥 4배 | ❌ 제한적 |

## 3. 데이터/트래픽 문제

### 실제 트래픽

| 항목 | 크기 | 빈도 |
|------|------|------|
| STT 결과 (텍스트) | ~100 bytes | 초당 1회 |
| AI 결과 (라벨) | ~50 bytes | 초당 1회 |

**초당 ~150 bytes = 무시해도 됨!**

## 4. 계획이 무리인가?

### 분석

| 항목 | 판단 |
|------|------|
| **상시 AI (브라우저)** | ⚠️ 도전적이지만 가능 |
| **데이터 수집** | ✅ 오히려 좋음! 실제 케이스 확보 |
| **트러블슈팅** | ✅ 문제 발견하면 최적화 |

### 결론

> **무리 아님!** 일단 해보고, 문제 생기면 최적화하자.
> 
> 실제 게임에서 문제가 될지는 **테스트해봐야 앎**.

## 6. 단계별 접근

```
Phase 1: 일단 상시 AI로 구현
         ↓
Phase 2: 실제 게임에서 테스트
         ↓
Phase 3: 문제 발견 시 → 키워드 필터 추가
         ↓
Phase 4: 그래도 문제면 → 서버 오프로딩 검토
```
