## 🎮 프로젝트 소개

### 게임 컨셉

**EchoForest(메아리 숲)**는 **4명이 한 팀**으로 **말조심**해야 하는 협동 게임입니다.  
음성 채팅에서 부정적 발언이 감지되면 AI가 이를 탐지하여 **팀 공용 저주 스택**이 쌓입니다.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    4인 협동 (피코파크 스타일)                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Player 1  →  "씨발" (+5)  ─┐                                       │
│  Player 2  →  "바보" (+1)  ─┼─→  팀 공용 저주 스택  ████████░░ 8/10  │
│  Player 3  →  "짜증나" (+3) ─┤                                       │
│  Player 4  →  (안말함)     ─┘                                       │
│                                                                     │
│                          스택 10 도달 시                             │
│                               ↓                                     │
│                      💀 4명 중 랜덤 1명 저주!                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 핵심 메커니즘

| 메커니즘 | 설명 |
|---------|------|
| **팀 공용 스택** | 누가 욕해도 같은 스택에 쌓임 (최대 10) |
| **심각도별 증가** | 1단계=+5, 2단계=+3, 3단계=+1 |
| **배치 누적** | 5초간 모은 발화의 **모든 부정어가 각각** 스택에 누적 |
| **저주 발동** | 스택 10 도달 시 4명 중 랜덤 1명 저주 |
| **저주 해제** | 버튼 + 긍정어(뽀뽀/사랑해/좋아해) 발화 시 해제 |
| **맵별 효과** | 숲(속도↓), 동굴(시야↓), 늪지(스턴+점프↓) |

### 프로젝트 차별점

- **실시간 음성 분석**: Web Speech API + AI 서버 연동으로 실시간 욕설 탐지
- **데이터 기반 최적화**: 모델 공식 권장값이 아닌 실제 게임 환경 데이터로 최적화
- **세분화된 제재**: 3단계 심각도로 스택 증가량 차등 적용

### 하이브리드 아키텍처 설계

| 처리 위치 | 태스크 | 이유 |
|----------|--------|------|
| **Client (On-device)** | 모션 인식 (MediaPipe), 긍정어 매칭 | 빠른 반응 필요, 서버 부하 감소 |
| **Game Server** | 팀 저주 스택 관리, 저주 발동/해제 | 중앙 집중식 상태 관리 |
| **AI Server** | 욕설/혐오 발언 탐지, 스택 증가량 계산 | 보안 중요, 모델 크기 큼 (400MB) |

## 🔮 저주 스택 시스템

### 스택 규칙

| 항목 | 값 | 설명 |
|------|-----|------|
| 최대 스택 | **10** | 스택이 10 도달 시 저주 발동 |
| 1단계 (Critical) | **+5** | 심각한 욕설 (씨발, 개새끼 등) |
| 2단계 (Severe) | **+3** | 중간 욕설 (짜증나, 열받네 등) |
| 3단계 (Mild) | **+1** | 경미한 부정어 (바보, 멍청이 등) |
| 저주 발동 후 | **0으로 초기화** | 스택 리셋 |

### 배치 처리 예시

> [!IMPORTANT]
> **배치 내 모든 부정어는 각각 스택에 누적됩니다!**

```
5초간 발화: "야 바보야" + "너 멍청이다" + "씨발"

AI 서버 분석 결과:
├── "야 바보야"   → severity 3 (mild)     → +1 스택
├── "너 멍청이다" → severity 3 (mild)     → +1 스택  
├── "씨발"       → severity 1 (critical) → +5 스택
└── total_stack_delta = 7

게임 서버: 팀 스택에 +7 추가 → ████████░░ 8/10 → ██████████ 10/10 초과!
         → 💀 4명 중 랜덤 1명 저주 발동!
```

### 맵별 저주 효과

| 맵 | 저주 이름 | 효과 | 지속시간 |
|-----|----------|------|---------|
| **맵 1: 숲** | 🌿 덩굴 속박 | 이동속도 50% 감소 | 10초 |
| **맵 2: 동굴** | 🦇 어둠의 눈 | 시야 반경 50% 감소 | 8초 |
| **맵 3: 늪지** | 🐸 늪지 함정 | 3초간 행동 불가 + 이후 점프력 50% 감소 | 3초 + 7초 |

### 저주 해제

```
저주 발동! → 팀원 A가 버튼 누름 → "사랑해" 발화 → ✨ 저주 해제!

유효 긍정어: 뽀뽀, 사랑해, 좋아해 (프론트엔드 로컬 매칭)
```

## 🤖 AI 모델 상세

### Smilegate unSmile 모델

| 항목 | 내용 |
|------|------|
| **모델명** | [smilegate-ai/kor_unsmile](https://huggingface.co/smilegate-ai/kor_unsmile) |
| **아키텍처** | BERT 기반 다중 레이블 분류 |
| **모델 크기** | ~400MB |
| **기능** | 한국어 혐오 발언 탐지 및 카테고리 분류 |
| **출력** | 10개 카테고리별 확률값 + 스택 증가량 |

### 분류 카테고리 (10개)

| 카테고리 | 설명 | 예시 |
|---------|------|------|
| 여성/가족 | 여성, 가족 대상 혐오 | 김치녀, 맘충 |
| 남성 | 남성 대상 혐오 | 한남충 |
| 성소수자 | 성소수자 대상 혐오 | - |
| 인종/국적 | 인종, 국적 차별 | 짱깨 |
| 연령 | 나이 차별 | 급식충, 틀딱 |
| 지역 | 지역 비하 | - |
| 종교 | 종교 차별 | - |
| 기타 혐오 | 분류 외 혐오 표현 | 장애인 비하 |
| **악플/욕설** | 일반 욕설, 비속어 | 씨발, 개새끼 |
| clean | 정상 발화 | 안녕하세요 |

### 심각도 단계와 스택 증가량

| Severity | Label | Confidence | 스택 증가량 | 예시 |
|----------|-------|------------|-------------|------|
| **1** | `critical` | 80% 이상 | **+5** | 씨발, 개새끼, 병신 |
| **2** | `severe` | 50~80% | **+3** | 짜증나, 열받네, 닥쳐 |
| **3** | `mild` | 10~50% | **+1** | 바보, 멍청이, 미치겠다 |
| **0** | `clean` | 10% 미만 | **0** | 안녕하세요, 잘했어 |

## 📊 성능 지표 및 최적화

### 핵심 성능 요약

| 지표 | 값 | 측정 조건 |
|------|-----|----------|
| **F1 Score** | **0.955** | Threshold 0.1, 71개 실제 음성 샘플 |
| **Accuracy** | **95.8%** | 전체 정확도 |
| **Precision** | **94.1%** | 욕설 판정 정밀도 (오제재 최소화) |
| **Recall** | **97.0%** | 욕설 탐지율 (미탐지 최소화) |
| **응답 속도** | **~50ms** | CPU 기준, 싱글톤 패턴 적용 후 |
| **GPU 가속** | **10배** | 단건 추론 기준 (50ms → 5ms) |

### Threshold 최적화

| Threshold | Accuracy | Precision | Recall | F1 Score | 분석 |
|:---------:|:--------:|:---------:|:------:|:--------:|:-----|
| **0.10** | **95.8%** | **94.1%** | **97.0%** | **0.955** | ✅ **최적값 선정** |
| 0.174 | 93.0% | 96.7% | 87.9% | 0.921 | Smilegate 공식값 |

> 공식값(17.4%) 대비: **Recall +9.1%p**, FN 4건→1건 감소

## 💡 개발하며 배운 핵심 인사이트

### 1. 공식 권장값 ≠ 서비스 최적값

**상황**: Smilegate unSmile 모델의 공식 threshold는 17.4%

**깨달은 점**:
- 공식 값은 **일반적인 혐오 표현** 탐지에 최적화
- 우리 서비스는 **게임 채팅 환경**이므로 사용 패턴이 다름
- **독자적인 데이터 수집 및 분석 필수**

> **결론**: 모델 개발자의 권장값을 맹신하지 말고, 실제 서비스 데이터로 검증하고 조정해야 한다.

### 2. 배치 처리의 중요성

**실시간 처리 vs 배치 처리**:
```
❌ 실시간: 발화마다 API 호출 → 네트워크 비용 증가, 서버 부하
✅ 배치: 5초간 모아서 1회 호출 → 효율적, "저주"라는 게임 설정과도 맞음
```

### 3. 싱글톤 패턴의 실질적 효과

모델을 서버 시작 시 1회만 로드하여 응답 속도 **100배 향상** (~5초 → ~50ms)

### 4. CPU vs GPU 성능 차이

| 작업 | CPU | GPU | 배속 |
|------|-----|-----|------|
| 단건 추론 | 50ms | 5ms | **10배** |
| 배치(32개) | 1,200ms | 30ms | **40배** |

### 빠른 테스트 (Python)

```python
import requests
import json

# 배치 분석 테스트 (핵심!)
response = requests.post(
    'http://localhost:8000/api/v1/analyze/batch',
    json={'texts': ['야 바보야', '너 멍청이다', '씨발']}
)
result = response.json()

print(f"총 부정어 수: {result['negative_count']}")
print(f"총 스택 증가량: {result['total_stack_delta']}")  # 7 예상
```

4. **Fine-tuning**: 게임 채팅 특화 데이터로 모델 미세조정
