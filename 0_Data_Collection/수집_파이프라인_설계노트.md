# 🎙️ UnSmile STT 데이터 수집 및 처리 가이드

이 문서는 UnSmile 모델의 Fine-tuning을 위해 **유튜브 영상에서 음성 데이터를 추출하고, 이를 학습 가능한 텍스트 데이터로 변환하는 전체 과정**을 설명합니다.

> ⚠️ **옛 파일명 주의**: 본문의 `youtube_downloader.py` · `audio_transcriber.py` · `auto_labeler.py` 등은 **예전 이름**입니다. 현재 실제 스크립트는 [`01_download/01_youtube_downloader.py`](01_download/01_youtube_downloader.py) · [`02_stt/02_whisper_transcriber.py`](02_stt/02_whisper_transcriber.py) · [`03_clean/03_text_clean.py`](03_clean/03_text_clean.py) · [`04_anonymize/04_text_anonymize.py`](04_anonymize/04_text_anonymize.py) · [`05_advanced_clean/05_text_clean_advanced.py`](05_advanced_clean/05_text_clean_advanced.py)입니다. 이 문서는 *왜 이런 구조가 됐는지*(아래 "변경 이력") 기록용으로 남겼습니다.

## 🛠️ 환경 설정 (Prerequisites)

이 도구들은 `unsmile` conda 환경에서 실행하는 것을 권장합니다.

```bash
# 1. Conda 환경 생성 및 활성화
conda create -n unsmile python=3.9
conda activate unsmile

# 2. 필수 시스템 패키지 (오디오 변환용)
conda install ffmpeg -c conda-forge

# 3. Python 라이브러리 설치
# (PyTorch GPU 버전 설치 후)
pip install yt-dlp openai-whisper pandas transformers
```

## 🚀 워크플로우 (Step-by-Step)

데이터 수집 과정은 안정성을 위해 **다운로드 - 변환 - 라벨링** 3단계로 분리되어 있습니다.

### Step 1. 수집할 영상 리스트 작성
`fine-turning/data_collection/url_list.txt` 파일을 생성하고, 수집하고 싶은 유튜브 링크를 한 줄에 하나씩 입력합니다.

```text
https://www.youtube.com/watch?v=example1
https://www.youtube.com/watch?v=example2
...
```

### Step 2. 오디오 다운로드 (Youtube Downloader)
영상에서 오디오만 추출하여 `mp3` 파일로 저장합니다. 
*   **특징**: 플레이리스트 링크라도 개별 영상만 다운로드하며, 403 에러 우회(iOS 모드)가 적용되어 있습니다.

```bash
python data_collection/youtube_downloader.py
```
*   **결과물**: `data_collection/raw_audio/` 폴더에 `audio_n.mp3` 생성

### Step 3. STT 변환 (Audio Transcriber)
다운로드된 오디오 파일을 OpenAI Whisper 모델을 사용하여 텍스트로 변환합니다.
*   **특징**: **청킹(Chunking)** 전략이 적용되어, 통 문장이 아닌 **발화 단위(Segment)**로 줄바꿈되어 저장됩니다.

```bash
python data_collection/audio_transcriber.py
```
*   **결과물**: `data_collection/raw_data/` 폴더에 `audio_n.txt` 생성

### Step 4. 자동 라벨링 (Auto Labeler)
수집된 텍스트(Raw Text)를 기존 UnSmile 모델(`smilegate-ai/kor_unsmile`)에 통과시켜, 혐오 표현 여부를 미리 예측(Pseudo-Labeling)합니다.

```bash
python data_collection/auto_labeler.py
```
*   **결과물**: `data_collection/auto_labeled_result.csv` (TSV 포맷)
*   **사용법**: 생성된 파일을 엑셀로 열어 **[Auto_Check]** 컬럼을 참고하여 검수 및 수정을 진행합니다.

## 📜 변경 이력 및 의사결정 과정 (History)

이 파이프라인이 왜 현재의 구조를 갖게 되었는지에 대한 기록입니다.

### 1. 통합 스크립트에서 기능 분리 (`stt_collector.py` → 3개 파일)
*   **초기**: 다운로드와 STT 변환을 한 번에 수행하는 단일 파일(`stt_collector.py`)로 시작.
*   **문제점**: 긴 영상(2시간 이상)을 처리할 때 시간이 오래 걸리며, 중간에 에러가 나면 다운로드부터 다시 해야 하는 비효율 발생. 코드가 복잡해짐(Spaghetti Code).
*   **결과**: 
    *   `youtube_downloader.py`: 다운로드 전담 (실패 시 재시도 용이)
    *   `audio_transcriber.py`: 변환 전담 (GPU 작업 집중, 이어하기 가능)
    *   `auto_labeler.py`: 후처리 전담

### 2. 청킹(Chunking) 전략 변경
*   **초기**: STT 결과 전체를 하나의 긴 텍스트로 저장.
*   **문제점**: 학습 데이터는 댓글/채팅 단위(단문)여야 하는데, 스크립트 전체는 너무 길어서 학습 효율이 떨어짐.
*   **해결**: Whisper 모델의 `segments` 정보를 활용하여, **사람이 숨을 쉬거나 문장이 끝나는 발화 단위**로 텍스트를 잘라서 저장하도록 변경.

### 3. 다운로드 안정성 확보 (403 Forbidden)
*   **이슈**: 유튜브의 봇 차단 정책으로 인해 다운로드 실패 빈번.
*   **해결**: `User-Agent` 헤더 추가 및 **iOS 클라이언트 모방(Client Spoofing)** 옵션을 적용하여 차단 우회 성공.

### 4. STT 특화 전처리 (Consonant Removal)
*   **이슈**: 기존 UnSmile 데이터셋은 인터넷 용어(ㅋㅋ, ㅎㅎ)가 많지만, STT 결과물은 음성 기반이라 자음/모음 단독 표기가 거의 없음.
*   **해결**: 학습 시 데이터의 도메인 차이를 줄이기 위해, 기존 데이터셋에서도 자음/모음을 제거하는 전처리 로직(`clean_text_for_stt`) 도입.
